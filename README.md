# Vent au comptoir — مرجع العمل المختصر

- **الإصدار المرجعي للحزمة:** v0.5.4
- **تاريخ الإصدار:** 2026-10-16
- **حالة التوثيق:** تنظيم تشغيلي موحد؛ نطاق MVP معتمد من صاحب المشروع، وإذن التنفيذ مستقل وغير ممنوح.
- **حالة التنفيذ:** **غير مصرح به**. لا برمجة ولا مشروع قابل للبناء ولا migrations ولا نشر قبل إذن صريح مستقل.

## نقطة البداية الإلزامية

ابدأ بـ `AGENTS.md` ثم `PROJECT_RULES.md`. بعد ذلك اقرأ فقط مرجع المنتج أو المتطلبات اللازم للمهمة. لا تقرأ الأرشيف كاملًا في الروتين اليومي.

## المراجع النشطة التسعة

1. `README.md` — خريطة البداية وحالة الحزمة.
2. `PROJECT_RULES.md` — القواعد الحاكمة وبوابة التنفيذ.
3. `AGENTS.md` — بروتوكول الوكلاء، المهام، التسليم، والتعارضات.
4. `docs/PRODUCT_MASTER.md` — الرؤية وحدود المنتج والمبادئ.
5. `docs/MVP_AND_ACCEPTANCE.md` — **نطاق MVP ومعايير قبوله المعتمدة**.
6. `docs/TECHNICAL_AND_SAFETY_RULES.md` — قواعد التقنية والبيانات وAI والأمان والمزامنة.
7. `docs/DECISIONS_AND_OPEN_GATES.md` — سجل حالة القرارات والبوابات المفتوحة؛ المرجع التشغيلي للحالة الحالية.
8. `docs/ARCHIVE_INDEX.md` — فهرس الوثائق التاريخية عند الحاجة فقط.
9. `docs/FINAL_HANDOFF_AND_CLOSEOUT_v0.5.4.md` — سجل الإقفال والتسليم الموحد؛ يمنع إعادة فتح مرحلة التوثيق دون سبب جوهري.

## ترتيب السلطة عند التعارض

1. آخر قرار صريح موثق من صاحب المشروع.
2. `PROJECT_RULES.md` للقيود الحاكمة ومنع التنفيذ.
3. `docs/DECISIONS_AND_OPEN_GATES.md` لحالة القرارات والبوابات.
4. بقية المراجع النشطة ضمن مجالها.
5. `archive/` تاريخي فقط، ولا يتغلب على مرجع نشط أو قرار أحدث.

إذا تعارض مرجعان نشطان أو تعذر تحديد القرار الأخير، لا تخمّن: أوقف الجزء المتأثر وسجّل التعارض.

## حالة القرارات والاختبارات

- اتجاه المنتج العام وقيود الخصوصية وسلامة البيانات وقرار منع التنفيذ قائم.
- نطاق MVP في `docs/MVP_AND_ACCEPTANCE.md` **معتمد: نواة P0 إلزامية ووحدات P1 اختيارية**.
- بوابة التنفيذ غير مفتوحة. لا تمنح هذه الحزمة إذنًا بالبرمجة.
- اختبارات القبول خطط مستقبلية؛ لا تُعرض بوصفها اختبارات منفذة.
- فصلنا في v0.5.4 بين P0 الإلزامي وP1 الاختياري لتقليل مخاطر توسع MVP.
- سجل Q1–Q247 محفوظ في الأرشيف وهو إعادة بناء تاريخية، وليس تفريغًا حرفيًا كاملًا.

## سياسة التوثيق

لا تُنشئ ملفًا جديدًا إذا أمكن تحديث المرجع النشط المناسب. لا تكرر محتوى موجودًا. تُحفظ التفاصيل القديمة في الأرشيف، ويُحدّث الفهرس عند نقل أو إضافة وثيقة. كل حزمة إصدار يجب أن تحتوي بيان إصدار وManifest محدثًا.
