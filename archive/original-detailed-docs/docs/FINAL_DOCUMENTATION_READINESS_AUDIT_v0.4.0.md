# التدقيق النهائي لجاهزية التوثيق — v0.4.0

- **التاريخ:** 2026-10-16
- **الحالة:** تدقيق توثيقي؛ لا يمثل اعتمادًا نهائيًا للتنفيذ ولا إذنًا بالبرمجة.
- **النطاق:** الاتساق بين الدستور، وسجل Q1–Q247، ومصفوفة التتبع، وخطة MVP، وخطط الاختبار، والوثائق التقنية والتجارية والحوكمة.

## الخلاصة التنفيذية

الحزمة منظمة بما يكفي للانتقال إلى **جلسة قرار تنفيذية قصيرة**، لكنها لا تثبت بعد أن المشروع جاهز للبرمجة. لا يوجد تناقض جديد يبرر تغيير قرار معتمد؛ توجد فجوات توثيقية/تحقق يجب عدم إخفائها.

## ما تم التحقق منه في هذه المراجعة

1. وجود `PROJECT_BLUEPRINT.md` وسجل Q1–Q247 ومصفوفة تتبع المتطلبات ووثائق MVP والاختبار والقرارات التقنية المفتوحة.
2. سجل القرارات يضم أرقام Q1 إلى Q247 متسلسلة في جدول واحد؛ هذا يثبت الترقيم، لا صحة استرجاع كل محادثة حرفيًا.
3. اتجاه `.NET/C#` و`Blazor` و`PostgreSQL` موثق كاتجاه عام معتمد، مع إبقاء تفاصيل التنفيذ بحاجة إلى تحقق.
4. بوابة منع البرمجة/النماذج/الترحيلات/النشر قبل الإذن الصريح محفوظة في الوثائق الحاكمة.
5. الخصوصية المحلية، وعدم القياس التلقائي، والعمل دون اتصال، وعدم فقد العمليات أو حجب بيانات التاجر، مذكورة كقيود حاكمة.

## الفجوات الحقيقية المتبقية

### 1. مصفوفة المتطلبات ليست تفصيلًا واحدًا لكل قرار

المصفوفة الحالية تجمع المتطلبات في مجموعات (26 مجالًا رئيسيًا). هذا مفيد للمراجعة العامة، لكنه لا يحقق وحده تتبعًا تفصيليًا لكل متطلب فرعي مستقل. عند بدء التحليل التفصيلي يجب تقسيم المجموعات التي تختلف في معيار القبول أو المخاطر إلى معرفات `REQ-*` مستقلة، وربط كل واحد باختبار ودليل ومرحلة.

**الأثر:** لا يجوز استخدام عبارة «كل متطلب له اختبار» حتى تُستكمل هذه الخطوة وتُسجل نتائج الاختبار الفعلية.

### 2. سجل Q1–Q247 إعادة بناء، لا محضر حرفي

السجل يحفظ 247 نقطة قرار وفق الملخص التاريخي المتاح، لكنه يصرّح بأنه ليس تفريغًا حرفيًا لكل سؤال وجواب. أي تفصيل دقيق غير ظاهر في المصدر يجب أن يبقى بحاجة تحقق، لا أن يُملأ بالحدس.

### 3. نطاق MVP ما زال خط أساس تخطيطيًا

البيع المحلي والتهيئة دون مخزون والذكاء الاصطناعي المنضبط محددة كاتجاه، لكن نطاق كل شاشة/عملية ومعايير القبول الدقيقة تحتاج مراجعة واعتمادًا منفصلًا. لا تساوي حالات القبول المقترحة نجاح الاختبارات.

### 4. لا يوجد تحقق ميداني للأجهزة والتشغيل

لم تثبت الحزمة التوافق الفعلي مع طابعة أو قارئ باركود أو درج نقدي أو ميزان بعينه. كما لم يُختبر تثبيت قاعدة البيانات أو الانقطاع أو التحديث أو الاستعادة على جهاز فعلي.

### 5. الامتثال القانوني ليس شهادة مطابقة

الوثيقة القانونية بحث أولي وتحدد بوابات تحقق. ما زال يلزم تأكيد المستندات والحقول والضرائب وقواعد الفوترة/الصندوق المنطبقة على النشاط المختار بواسطة مصادر رسمية حديثة ومختص جزائري قبل الإصدار التجاري.

### 6. النموذج التجاري لا يحتوي أسعارًا أو توقعات مثبتة

الباقات ومبادئ الترخيص موثقة، لكن الأسعار والتكلفة الفعلية لاستهلاك AI والدعم والتوزيع واكتساب العملاء تحتاج بيانات أو عروض أسعار وتجربة، ولا ينبغي اختلاقها.

### 7. لا توجد نتائج اختبار أو تدقيق أمني فعلي

خطط QA والأمن تحدد ما يجب اختباره فقط. لا يوجد ادعاء بأن اختبارات برمجية أو اختراق أو استعادة فعلية قد نُفذت.

## قرار الجاهزية

| البوابة | الحالة | ما يلزم لإغلاقها |
|---|---|---|
| اكتمال الرؤية ونطاق المنتج العام | موثق بدرجة جيدة | لا تغيير إلا عند ظهور تعارض موثق أو قرار جديد من Farid |
| حفظ نقاط القرار التاريخية | 247 نقطة مرقمة | مراجعة مقابل السجل الأصلي عند توفره؛ لا ندّعي الحرفية |
| تفصيل متطلبات قابلة للاختبار | جزئي | تفكيك مجموعات المصفوفة إلى REQ فرعية ومعايير مستقلة |
| MVP ومعايير القبول | مقترح تخطيطي | اعتماد منفصل لنطاق النسخة الأولى وحدودها |
| اختيار التقنية التفصيلي | غير محسوم بالكامل | إذن منفصل بنموذج تقني محدود ثم اختبار ومقارنة موثقة |
| الأجهزة والتوافق | غير مختبر | جرد أجهزة فعلية واختبار التوافق |
| الامتثال الجزائري | يحتاج تحققًا متخصصًا | مراجعة قانونية/ضريبية لنشاط ومستندات محددة |
| التكلفة والمدة والفريق | غير محسوم | تقدير مبني على نطاق معتمد وتجارب ومخاطر |
| الأمن والاستعادة والتحديث | تصميم موثق، غير مختبر | اختبارات فعلية موثقة قبل التجربة والإطلاق |
| الإذن بالتنفيذ | **غير ممنوح** | موافقة صريحة منفصلة من Farid |

## أقصر مسار عملي تالٍ

1. اعتماد أو تعديل نطاق MVP ومعايير القبول المقترحة؛ لا نعيد مناقشة النطاق الكامل.
2. حصر جهاز Windows والطابعة/الماسح المتاحين فعليًا؛ إذا لم تتوفر أجهزة، تُسجل هذه الفجوة ولا يُدعى التوافق.
3. بعد إذن صريح منفصل، إجراء تجربة تقنية محدودة لاختبار التغليف والطباعة والتخزين المحلي والنسخ/الاستعادة وأداء AI على عينة مهام.
4. استخدام نتائج التجربة لتقدير الفريق والمدة والتكلفة، ثم اتخاذ قرار مستقل ببدء التنفيذ.

## ضوابط لا يجوز كسرها

- لا كود منتج، ولا مشروع قابل للتشغيل، ولا migrations أو prototype أو نشر قبل الإذن الصريح.
- لا تُسقط الوحدات المؤجلة من الرؤية الكاملة بسبب عدم دخولها MVP.
- لا تُحوّل الحالة `PROPOSED` أو `NEEDS-VALIDATION` إلى `APPROVED` دون دليل أو موافقة.
- لا تُعلن نتيجة اختبار إلا بوجود دليل مسجل.
- لا قياس تلقائي أو إرسال بيانات إلى السحابة دون إعداد/موافقة صريحة مناسبة.
- لا حجب لبيانات التاجر بسبب انتهاء الاشتراك.

## سجل التغييرات

- **v0.4.0:** إضافة تدقيق جاهزية نهائي يميز بين اكتمال التوثيق العام وبين اكتمال المتطلبات التفصيلية والاختبارات الفعلية. لا يغيّر قرارات المنتج ولا يمنح إذنًا بالتنفيذ.
