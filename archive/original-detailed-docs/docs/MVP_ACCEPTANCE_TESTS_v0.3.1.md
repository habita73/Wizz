# حالات قبول MVP — Vent au comptoir

- الإصدار: 0.3.1
- الحالة: **PROPOSED — للمراجعة والاعتماد قبل التنفيذ**
- المرحلة: توثيق وتحليل فقط؛ لا يوجد إذن بالبرمجة.
- الغرض: تحويل نطاق MVP المقترح إلى سيناريوهات قابلة للاختبار. هذه الحالات لا تعني أن وظائف البرنامج موجودة أو اجتازت الاختبار.

## قواعد التقييم

- **PASS:** تحقق الناتج المتوقع بدليل قابل للتكرار.
- **FAIL:** لم يتحقق الناتج أو حدث فقد/تكرار/تجاوز صلاحية.
- **BLOCKED:** لا يمكن الاختبار قبل حسم قرار أو توفير جهاز/بيئة.
- كل اختبار يُنفذ ببيانات اصطناعية أولًا، ويُسجّل إصدار البرنامج والبيئة والخطوات والنتيجة والدليل.
- أي فشل يمس سلامة البيانات أو الصلاحيات أو النسخ والاستعادة يمنع قبول النسخة.

## اختبارات ممنوعة قبل حسم المتطلبات

1. لا يُعتمد قالب فاتورة أو وثيقة تسليم بوصفه مطابقًا قانونيًا قبل مراجعة النصوص الحالية من مختص جزائري.
2. لا يُعلن توافق الطابعات أو قارئات الباركود قبل تحديد الطرازات واختبارها.
3. لا تُثبت حدود أداء رقمية دون جهاز مرجعي وبيانات اختبار.
4. لا يُختبر إرسال بيانات فعلية إلى خدمة ذكاء اصطناعي سحابية دون إعداد الخصوصية والموافقة المناسبة.
5. لا تُجرى اختبارات الترحيل أو الاستعادة على بيانات حقيقية وحيدة النسخة.

## معيار قبول MVP المقترح

- اجتياز جميع حالات P0؛ لا يُقبل أي فشل في سلامة البيانات أو الصلاحيات أو الخصوصية أو عدم التكرار أو الاستعادة.
- حالات P1 إما ناجحة أو موثقة صراحةً بأنها خارج نطاق النسخة التجريبية، مع عدم الادعاء بتوفرها.
- كل حالة لها دليل اختبار ونتيجة وبيئة وإصدار.
- مراجعة بشرية لمخرجات الذكاء الاصطناعي، مع عدم اعتبار النص المولّد مصدرًا موثوقًا للحسابات التجارية.
- موافقة صاحب المشروع مطلوبة قبل اعتبار هذه المعايير معتمدة، وقبل الانتقال إلى البرمجة.

## التبعيات المفتوحة

- اختيار جهاز Windows مرجعي ومواصفاته.
- تحديد طرازات الطابعة وقارئ الباركود، إن وجدا.
- حسم التفاصيل التقنية للتخزين المحلي والتثبيت والتحديث.
- تحديد نماذج الذكاء الاصطناعي المتاحة وتكلفتها ومتطلبات الخصوصية.
- مراجعة المستندات والالتزامات القانونية والضريبية في الجزائر.
