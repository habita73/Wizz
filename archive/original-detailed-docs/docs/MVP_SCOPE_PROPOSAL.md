## 1. الهدف
إطلاق تجربة ميدانية محدودة لبرنامج بيع وإدارة تجارية محلي لتاجر صغير، تكون عملية البيع الأساسية موثوقة وسريعة، وتعمل دون اتصال، مع مساعد ذكاء اصطناعي حقيقي لكن محكوم بالصلاحيات والتأكيد والتسجيل. لا يعني اختيار MVP حذف بقية نطاق المنتج؛ كل الوحدات الأوسع تبقى ضمن الرؤية المرحلية الموثقة.

## 2. داخل النطاق المقترح

### A. الإعداد والهوية
- إعداد مؤسسة/محل واحد، العملة الأساسية وإعدادات اللغة والمنطقة، والبدء السريع مع إمكانية إكمال الإعداد لاحقًا.
- مستخدمون محليون وأدوار وصلاحيات أساسية؛ كلمة مرور للإدارة ورمز PIN سريع للعمليات اليومية وفق الصلاحيات.
- واجهة عربية RTL أولًا، وإعداد مستقل للغة الواجهة ولغة المساعد ولغة المستندات؛ الفرنسية ضمن التحقق الأولي.

### B. المنتجات والبيع
- تعريف المنتجات والرموز الداخلية والباركود والاسم والوحدات والأسعار.
- بحث سريع ومسح باركود متى دعمه الجهاز، وتدفق بيع مختصر مع الكميات والخصم المصرح به.
- بيع نقدي أو آجل، تسجيل دفعة كاملة أو جزئية وطرق دفع قابلة للتهيئة دون افتراض تكامل إلكتروني مباشر.
- إيصال/مستند بيع أساسي قابل للطباعة، مع دعم طابعة متوافقة بعد اختبار فعلي.
- إرجاع أو تصحيح/إلغاء مضبوط للمعاملات المؤكدة عبر سجل تدقيق؛ لا محو صامت للسجلات.

### C. المخزون الأساسي — قابل للتعطيل
- يمكن تشغيل المحل بوضع **المبيعات فقط دون إدارة مخزون**، أو تفعيل المخزون من الإعدادات.
- عند التفعيل: أرصدة أولية، حركات ناتجة عن البيع والشراء/التعديل المصرح به، تنبيه نفاد بسيط وجرد أساسي.
- منع الأرصدة/الحركات غير المتسقة أو إظهار تحذير مضبوط حسب نوع الخطأ؛ كل تعديل مهم مسجل.
- لا تدخل في MVP التصنيع والتركيب، الدُفعات والصلاحية والتسلسل، تعدد المستودعات، أو إدارة المخزون المتقدمة إلا إذا أثبت الاختبار أنها ضرورة حاسمة للقطاع التجريبي.

### D. العملاء والديون والتقارير
- سجل عميل اختياري مرتبط بالمبيعات والمدفوعات والرصيد المستحق.
- تسجيل تسديدات جزئية ومتابعة الرصيد دون ادعاء أنه نظام محاسبة كاملة.
- تقارير تشغيلية أولية: المبيعات حسب الفترة، المنتجات الأكثر بيعًا، المدفوعات والأرصدة، ومؤشرات المخزون إذا كان مفعّلًا.
- تمييز القيم المحسوبة من التفسيرات أو التوقعات التي يولدها الذكاء الاصطناعي.

### E. الموثوقية والخصوصية
- قاعدة بيانات محلية ومواصلة الوظائف الأساسية دون الإنترنت.
- نسخ احتياطي محلي تلقائي، وإجراء استعادة موثق ومختبر قبل التجربة الميدانية.
- سجل تدقيق للعمليات الحساسة والتصحيحات وتغييرات الإعدادات.
- لا إرسال تلقائي للقياس أو تقارير الأعطال؛ مشاركة التشخيص تتطلب موافقة صريحة. مزامنة البيانات أو استخدام الذكاء الاصطناعي السحابي لهما موافقات وإعدادات منفصلة.
- استيراد أولي من ملف جدولي شائع مع معاينة والتحقق ومنع التكرار؛ تصدير بيانات تجارية أساسية بصيغة شائعة.

### F. الذكاء الاصطناعي في النسخة الأولى
- مساعد نصي عربي أولًا؛ دعم الفرنسية واللهجة الجزائرية يخضع لتقييم النموذج الفعلي.
- الإجابة عن أسئلة بيانات المحل عبر أدوات مقيدة وصلاحيات، لا عبر SQL أو وصول مباشر إلى قاعدة البيانات.
- تنفيذ إجراءات منخفضة المخاطر المصرح بها، مثل البحث وعرض الملخصات وتجهيز مسودة؛ طلب تأكيد قبل اعتماد البيع أو الإرجاع أو الخصم الحساس أو تعديل البيانات.
- بيان الافتراضات عند غموض الطلب، وعدم الادعاء بإتمام أي عملية قبل تأكيد النظام لها.
- سياسة محلية/سحابية بحسب القدرة والخصوصية والاتصال والتكلفة والخطة؛ سقف استخدام واضح، وبديل بسيط عند انقطاع الخدمة، مع استمرار وظائف البيع الأساسية إذا نفدت حصة AI.
- لا يشترط MVP صوتًا أو نموذجًا محليًا كبيرًا أو وكلاء متعددين أو محرر تدفقات بصريًا.

### G. الأجهزة والواجهة
- Windows Desktop هو مسار الاستخدام الأساسي المقترح، مع واجهة قابلة للاستخدام بلوحة المفاتيح واللمس.
- اختبار قارئ باركود يعمل كلوحة مفاتيح وطابعة إيصالات واحدة على الأقل من الأجهزة المتاحة قبل اعتماد التوافق.
- الهاتف في هذه المرحلة للمتابعة فقط إن كان ضمن تجربة مختارة؛ لا يُشترط تساوي وظائف الهاتف والحاسوب.

## 3. خارج MVP صراحةً — مع بقائه ضمن الرؤية العامة
تعدد الفروع والمستودعات المتقدم، المزامنة متعددة الأجهزة الإنتاجية، بوابة سحابية شاملة، تطبيق هاتف متكامل، التجارة الإلكترونية وقنوات البيع المتعددة، إدارة المشتريات المتقدمة وعروض الموردين، التصنيع/الوصفات، الولاء والحملات، التوصيل والأسطول، الموارد البشرية والرواتب، التأمين وإدارة المخاطر المؤسسية، البنوك والشيكات والتمويل، إدارة الأصول والصيانة، العقود والعلاقات الخارجية، الأتمتة متعددة الخطوات واسعة النطاق، التكاملات الحكومية/البنكية، الفوترة الإلكترونية الرسمية، ومصمم المستندات المتقدم.

لا يعني هذا رفضها أو حذفها؛ إنها مؤجلة حتى تُثبت الأولوية والجدوى والامتثال.

## 4. معايير قبول MVP
1. يستطيع مستخدم مخول إنشاء منتج وإتمام عملية بيع وطباعة مستندها على جهاز الاختبار.
2. لا تتكرر المعاملة عند إعادة المحاولة أو انقطاع التطبيق؛ وتبقى السجلات المالية والمخزنية متسقة.
3. يستمر البيع المحلي الأساسي دون إنترنت، وتُعرض بوضوح الوظائف التي تحتاج اتصالًا.
4. يمكن تعطيل المخزون بالكامل دون تعطيل البيع، ويمكن تفعيله دون خلط الأرصدة.
5. يمكن تسجيل دفعة جزئية ورصيد مستحق وإظهارها في تقرير واضح.
6. يمكن تصحيح/إرجاع معاملة مع حفظ أثر العملية الأصلية وسبب التصحيح وصلاحية المنفذ.
7. تنجح عملية نسخ احتياطي واستعادة فعلية من ملف النسخ، وتوثق النتيجة.
8. يمنع النظام المستخدم غير المخول من الإجراءات الحساسة، ويطلب التأكيد حسب السياسة، ويسجل النتيجة.
9. لا يرسل النظام بيانات أو تقارير تشخيص تلقائيًا؛ يظهر للمستخدم بوضوح متى تتطلب مهمة AI خدمة سحابية.
10. لا يُعلن عن توافق طابعة/قارئ أو نموذج AI قبل اختباره على جهاز فعلي وتوثيق النتيجة.
11. ينجح استيراد ملف عينة بعد المعاينة والتحقق، ويُمنع الاستيراد المكرر غير المقصود.
12. يجتاز الإصدار اختبارات المبيعات، الصلاحيات، العمل دون اتصال، سلامة البيانات، النسخ والاستعادة، والأجهزة، ثم تجربة محدودة بموافقة Farid قبل أي إطلاق عام.

## 5. قرارات يجب حسمها قبل التنفيذ
- القطاع/نوع التاجر الأول للتجربة، وعدد التجار والأجهزة في التجربة.
- هل يبدأ MVP بوضع المبيعات فقط افتراضيًا، أم تُفعّل إدارة المخزون في القطاع التجريبي؟ كلا الوضعين مطلوبان تصميميًا.
- المستندات الدقيقة التي ستطبع في MVP، وصيغتها بعد مراجعة قانونية محلية.
- الجهاز الفعلي والطابعة وقارئ الباركود ونظام Windows المستهدف.
- آلية تخزين قاعدة البيانات المحلية وخيار التغليف/التثبيت؛ يُحسمان بعد اختبار تقني، لا في هذه الوثيقة.
- نموذج AI الأول وخيار محلي/سحابي وحدود الاستخدام والتكلفة، بناءً على اختبار جودة وتكلفة وخصوصية.
- الميزانية والمدة والفريق وخطة الدعم للتجربة.
- مراجعة محاسب/مختص جزائري للنظام الضريبي والمستندات، ومختص عند الحاجة لمتطلبات حماية البيانات والامتثال.
