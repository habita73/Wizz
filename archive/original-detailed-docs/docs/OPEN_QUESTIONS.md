# المسائل المفتوحة والتحقق المطلوب — Vent au comptoir

هذه القائمة لا تعيد فتح القرارات المعتمدة. وهي تحدد تفاصيل لم تُحسم أو تحتاج تحققًا، وليست طلبًا من Farid لإعادة الإجابة عن كل شيء.

## تحقق تقني
- الاختيار الدقيق لنمط Blazor/التعبئة والتثبيت والتحديثات بعد مراجعة معمارية.
- تصميم التخزين المحلي/خادم المتجر، الترحيل، النسخ الاحتياطي والاستعادة، مع اختبار الأداء والتعافي.
- الحد الأدنى للأجهزة ونظام Windows والذاكرة والمعالج، ودعم الطابعات/قارئات الباركود/الأدراج/الموازين حسب الطراز.
- نموذج المزامنة وسياسة التعارض لكل مجال وحالات انقطاع الخادم الرئيسي.
- تقييم نماذج AI المحلية والسحابية للغة العربية واللهجة الجزائرية والفرنسية والصوت، ومتطلبات العتاد والسرعة والكلفة.
- اختيار التكاملات الخارجية وفق الترخيص والأمن والتكلفة والملاءمة؛ لا افتراض أن Telegram أو n8n أو أي مزود إلزامي.

## تحقق قانوني/سوقي
- المتطلبات الجزائرية الرسمية للفواتير والوثائق والضرائب وأنظمة الصندوق/نقاط البيع وحماية البيانات والاحتفاظ بالسجلات.
- قواعد الرواتب والتصريحات الاجتماعية والتأمينات والشيكات ووسائل الدفع عند انطباقها.
- النشاط/الشريحة الأولى للتجربة الميدانية، الأسعار، حدود الباقات، حدود AI، الرخصة ومددها وفترات السماح.
- قنوات البيع الإلكتروني والتوصيل ومزودو الدفع الفعليون، والتوافقات المتاحة.

## تخطيط مرحلي
- ترتيب وحدات الإصدار الأول النهائي وميزانيته ومدته بعد تقييم واقعي واختبارات جدوى.
- نطاق التجربة الميدانية ومعايير القبول ومجموعة التجار التجريبية.
- تفاصيل المزامنة السحابية والتعديل عن بعد؛ لا تعتبر متاحة افتراضيًا.

## قيود لا تتغير بسبب هذه القائمة
- لا برمجة أو scaffold أو migrations أو prototype قابل للتشغيل أو تعديل VPS قبل إذن صريح.
- لا تُسأل أسئلة إضافية في إدارة المخاطر؛ هذا المجال موثق بما يكفي وفق توجيه المستخدم.
- لا تُرسل بيانات أو telemetry تلقائيًا.
