# مصفوفة تتبّع المتطلبات التفصيلية — v0.4.1

- **التاريخ:** 2026-10-16
- **الحالة:** تفصيل توثيقي مقترح؛ ليس اعتمادًا نهائيًا لمتطلبات MVP ولا إذنًا بالتنفيذ.
- **المصدر:** `DECISION_TRACEABILITY_Q1-Q247.md`، والمصفوفة السابقة v0.3.9، والوثائق الحاكمة.
- **القيود الحاكمة:** `PROJECT_RULES.md` و`AGENTS.md`.
- **مهم:** لا يثبت وجود معيار قبول أن الاختبار قد نُفذ أو نجح. جميع الاختبارات أدناه مطلوبة مستقبلًا ما لم تُرفق أدلة فعلية مستقلة.

## معنى الحالات

- **APPROVED-DIRECTION:** اتجاه المنتج معتمد؛ التفاصيل هنا لا تصبح تلقائيًا مواصفات نهائية.
- **PROPOSED:** تفصيل تنفيذي مقترح يحتاج اعتمادًا قبل أن يصبح التزامًا على النسخة الأولى.
- **NEEDS-VALIDATION:** يحتاج مصدرًا موثوقًا أو تجربة تقنية/ميدانية أو رأيًا متخصصًا.
- **DEFERRED:** محفوظ في الرؤية العامة لكنه خارج المرحلة الأولى ما لم يُعتمد خلاف ذلك.
- **NOT-TESTED:** لا توجد نتيجة اختبار فعلية مثبتة في هذه الحزمة.

## قواعد التتبع

1. المعرفات ثابتة ولا يعاد استخدامها لمتطلب مختلف؛ عند التعديل تسجل مراجعة.
2. مراجع `Q` تشير إلى سجل القرارات المعاد بناؤه، وليست محضرًا حرفيًا للمحادثات.
3. معيار القبول يصف ما ينبغي إثباته؛ عمود الدليل يحدد الإثبات المطلوب لا نتيجة موجودة.
4. لا يصبح أي بند من MVP معتمدًا نهائيًا لمجرد ظهوره هنا.
5. يجب تقسيم أي بند لاحقًا إذا تبيّن أن له نتائج قبول أو صلاحيات أو مخاطر مستقلة.
