# خطة التحقق التقني المحدود — Vent au comptoir

- **الإصدار:** 0.3.3
- **الحالة:** PROPOSED — خطة تحقق فقط، وليست اعتمادًا للتنفيذ.
- **اللغة:** العربية
- **المرجع:** قرارات Q1–Q247، `PROJECT_RULES.md`، `AGENTS.md`، وخطة MVP.

## الهدف

تقليل المخاطر التقنية قبل طلب إذن التنفيذ، عبر اختبارات قصيرة ذات نتائج قابلة للملاحظة. لا تنشئ هذه الخطة مشروعًا برمجيًا، ولا تختار مكتبات نهائية، ولا تعتبر أي خيار ناجحًا قبل اختباره على جهاز فعلي.

## ترتيب العمل المقترح

1. **الآن — دون برمجة:** تحديد جهاز اختبار Windows، وأي طابعة/قارئ متاحين، أو توثيق عدم توفرها.
2. **قبل التنفيذ:** حسم نمطي النشر المستهدفين للـMVP: جهاز مستقل أولًا، وهل يلزم خادم محلي متعدد الأجهزة في الإصدار الأول أم يؤجل.
3. **بعد إذن صريح بالتنفيذ فقط:** تنفيذ تجارب تقنية صغيرة منفصلة، لكل منها سؤال واحد ونتيجة وقرار؛ لا تتحول التجارب إلى مشروع منتج دون موافقة.
4. **قبل قبول MVP:** تنفيذ حالات `MVP_ACCEPTANCE_TESTS` وتسجيل الأدلة الفعلية، لا الاكتفاء بأن الاختبار مخطط له.

## ما لا يُحسم بهذه الخطة

- لا اختيار نهائي لطراز طابعة أو قارئ باركود أو درج نقد.
- لا اعتماد نهائي لمزود AI أو نموذج بعينه.
- لا اعتماد قانوني أو ضريبي؛ المرجع القانوني يحتاج تحققًا مختصًا.
- لا تقدير نهائي للتكلفة أو المدة أو حجم الفريق.
- لا إذن بإنشاء Solution أو مشاريع .NET أو قواعد بيانات أو أي كود.

## سجل النتيجة المطلوبة لكل تجربة مستقبلية

لكل اختبار يسجل: رقم الاختبار، السؤال، الجهاز/الإصدار، الإعدادات، خطوات قابلة للتكرار، النتيجة المتوقعة، النتيجة الفعلية، الأدلة، المخاطر، القرار، وحالة القرار. لا تُكتب حالة `PASS` إلا بعد تنفيذ الاختبار وتوثيق النتيجة.
