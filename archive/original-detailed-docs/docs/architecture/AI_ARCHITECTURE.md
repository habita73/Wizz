# معمارية AI — نهج هجين: محلي أو سحابي بحسب المهمة

## الطبقات

اختيار التنفيذ محليًا أو سحابيًا ليس قاعدة ثابتة لصالح أحدهما؛ يُحدد بحسب المهمة وقدرة الجهاز والاتصال والخصوصية والكلفة ومستوى العرض. هذا توضيح للاتجاه المعتمد في المخطط، لا قرار بمزود أو نموذج محدد.
1. قواعد حتمية محلية للتقارير والتنبيهات والحسابات.
2. نموذج لغوي محلي لتفسير طلبات محددة وتوجيهها إلى وظائف مسموحة.
3. نموذج سحابي اختياري للمهام التي تحتاج قدرة أعلى.

## قواعد
- لا SQL حر ولا shell حر من النموذج.
- وظائف allowlisted بعقود ومعاملات محددة.
- التحقق من الصلاحيات وصحة البيانات في التطبيق.
- سؤال المستخدم إذا كان المنتج/المتجر/الزبون ملتبسًا.
- مسودة وموافقة للوثائق أو الإجراءات الحساسة.
- النتائج الرقمية من قاعدة البيانات لا من تخمين النموذج.
- إذا تعذر AI تستمر المبيعات.
- لا تُرسل بيانات إلى مزود سحابي دون إعداد وسياسة واضحة.
- لا نفترض أن كل جهاز Windows قادر على نموذج محلي قوي.

## أمثلة وظائف
GetSalesSummary, GetLowStockProducts, GetProductMovement, CreateDeliveryNoteDraft, CreatePurchaseOrderDraft, PrepareSupplierEmail, SendSupplierEmail (وفق صلاحية/موافقة).

## ما يحتاج تقييمًا
دقة العربية والفصحى واللهجات، دعم الفرنسية لاحقًا، RAM/CPU، زمن الاستجابة، حجم النموذج، تكلفة التحديث، ومتى نستخدم السحابة.
