# الدعم والصيانة والتشغيل بعد الإطلاق — v0.3.5

- التاريخ: 2026-10-16
- الحالة: **PROPOSED / NEEDS-VALIDATION**؛ خطة تشغيلية وليست التزام خدمة تعاقديًا.
- مرحلة المشروع: توثيق وتحليل وتصميم فقط؛ التنفيذ غير مصرح به.

## 1. المبادئ
1. لا تُرسل بيانات الاستخدام أو تقارير الأعطال تلقائيًا. يختار العميل التشخيص الذي يريد مشاركته عند طلب الدعم، بعد معاينته وموافقته.
2. الدعم عن بُعد اختياري ومحدد الغرض والمدة؛ لا يبدأ دون موافقة صريحة، ويمكن إنهاؤه، ويسجل الوصول والتغييرات.
3. لا تُحجز بيانات العميل أو تُعطل العمليات المحلية بسبب الاشتراك أو الحاجة إلى الدعم. تظل استمرارية النواة المحلية خاضعة لقواعد الترخيص المعتمدة.
4. لا يُعلن زمن استجابة أو SLA أو دعم دائم قبل تحديد القدرة والتكلفة واعتماد الشروط التجارية.
5. تخضع الإصلاحات والتحديثات للمراجعة والاختبار والنسخ الاحتياطي وخطة التراجع، مع حماية بيانات العميل وترحيلات قاعدة البيانات.

## 2. قنوات الدعم
- **مساعدة ذاتية:** دليل عربي، أسئلة شائعة، استكشاف أعطال ورسائل مفهومة؛ ويفضل إتاحتها محليًا.
- **تذكرة دعم:** وصف المشكلة، وقتها، إصدار البرنامج، ومعلومات الجهاز الطرفي عند الصلة. لا تُرفق قاعدة البيانات كاملة افتراضيًا.
- **حزمة تشخيص اختيارية:** عرض الحقول والملفات قبل الإرسال، استبعاد الأسرار والبيانات غير اللازمة، ثم موافقة المستخدم.
- **مساعدة عن بُعد:** موافقة صريحة، نطاق محدد، مدة محدودة، سجل جلسة، وإمكانية الإنهاء الفوري. لا تُخزن كلمات المرور أو رموز الجلسات في سجلات الدعم.

## 3. تصنيف البلاغات المقترح
| المستوى | مثال | الإجراء |
|---|---|---|
| P1 حرج | خطر على سلامة البيانات أو تعطل البيع المحلي على نطاق واسع | إرشاد لحماية البيانات، وقف التغييرات الخطرة، وتصعيد فني |
| P2 عالٍ | تعطل وظيفة أساسية مع حل مؤقت محدود | توثيق الأثر والحل المؤقت ثم إصلاح واختبار |
| P3 متوسط | خلل غير أساسي مع استمرار العمل | تسجيله وترتيبه ضمن دورة الصيانة |
| P4 منخفض | سؤال استخدام أو تحسين | إحالته للدليل أو قائمة التحسينات |

هذا تصنيف داخلي مقترح، وليس SLA تعاقديًا.

## 4. دورة معالجة البلاغ
1. تسجيل البلاغ بمعرّف فريد وتحديد موافقة المستخدم على أي تشخيص.
2. تقييم الأثر والأولوية وخطر البيانات أو المعاملات.
3. طلب الحد الأدنى من المعلومات اللازمة.
4. إعادة إنتاج المشكلة في بيئة اختبار ببيانات اصطناعية متى أمكن.
5. اقتراح حل مؤقت آمن دون حذف أو تعديل غير قابل للتراجع.
6. إصلاح ومراجعة واختبارات مناسبة، بما فيها التوافق والترحيلات عند الصلة.
7. نشر مرحلي مع خطة تراجع وحماية البيانات.
8. تأكيد النتيجة وتوثيق السبب والإجراء الوقائي وإغلاق البلاغ.

## 5. الإصدارات والصيانة
- تصنيف الإصدارات: إصلاحات أمنية، إصلاح أعطال، توافق، وميزات جديدة.
- لكل إصدار: ملاحظات إصدار، متطلبات مسبقة، تغييرات البيانات، اختبارات اجتياز، نسخة احتياطية وخطة تراجع.
- التوزيع مرحلي؛ لا يُنشر تحديث شامل قبل التحقق من مجموعة أولى.
- لا يُرجع البرنامج إلى إصدار أقدم فوق قاعدة بيانات أحدث إلا بخطة توافق مختبرة؛ قد تتطلب الاستعادة نسخة متوافقة.
- تُحدد إصدارات Windows وقاعدة البيانات والأجهزة الطرفية المدعومة بعد اختبارها؛ لا يُوعد بتوافق غير مثبت.
- لا تُستبدل الإعدادات والقوالب المعتمدة بصمت.

## 6. النسخ والاستعادة
- قبل إصلاح عالي المخاطر أو ترحيل بيانات، تحقق من نسخة حديثة قابلة للاستعادة.
- نجاح إنشاء النسخة لا يكفي؛ تُختبر الاستعادة دوريًا وتوثق النتيجة.
- عند خطر على سلامة البيانات، تحفظ الحالة قبل الإصلاح وتمنع محاولات قد تكرر المعاملات أو تضاعف الأرصدة.
- تُحدد أهداف RPO/RTO لاحقًا حسب نموذج النشر والتكلفة؛ لا تُخترع قيم قبل التحقق.

## 7. التشخيص والخصوصية
- التشخيص محلي افتراضيًا، والإرسال عملية منفصلة ومقصودة.
- توضح شاشة الإرسال الحقول والملفات والجهة المستلمة والغرض ومدة الاحتفاظ المقترحة.
- استبعاد كلمات المرور ومفاتيح الترخيص السرية ورموز الجلسات ومحتوى المعاملات غير اللازم.
- تقليل الاحتفاظ بملفات التشخيص وحصر الوصول إليها، مع سياسة حذف تُعتمد لاحقًا.
- لا تُستخدم بيانات العملاء لتدريب النماذج أو التحليلات العامة تلقائيًا.
- تخضع المعالجة السحابية أو النقل عبر الحدود لمراجعة قانونية منفصلة وإعدادات وموافقة مناسبة.

## 8. حدود المسؤولية
- لا يُضمن توافق طابعة أو قارئ أو جهاز طرفي لم يخضع للاختبار.
- لا تُعرض المعلومات المحاسبية أو الضريبية أو القانونية على أنها رأي رسمي دون مراجعة مختص.
- لا تُنسب شبهة احتيال إلى موظف بناءً على تنبيه آلي وحده؛ يلزم تحقق بشري وأدلة.
- لا يحق للدعم تعديل بيانات العميل مباشرة إلا بصلاحية وإجراء موثق وموافقة لازمة.

## 9. مؤشرات داخلية اختيارية
لا تُجمع تلقائيًا؛ يمكن حسابها من التذاكر أو السجلات التي وافق العميل على مشاركتها:
- عدد البلاغات حسب الأولوية والوظيفة والإصدار.
- زمن الحل الفعلي بعد بدء خدمة الدعم، دون وعد مسبق.
- البلاغات المتكررة والإصلاحات التي سببت تراجعًا.
- نجاح استعادة النسخ في اختبارات الصيانة.
- مشكلات الأجهزة الطرفية المتكررة.
- رضا العميل إذا اختار تقديم ملاحظاته.

## 10. قرارات مؤجلة
- ساعات الدعم وقنواته ولغاته.
- هل الدعم مشمول بكل باقة أم مدفوع، وحدوده لكل مستوى.
- أوقات الاستجابة والحل التعاقدية إن وجدت.
- الإصدارات المدعومة ونهاية الدعم.
- مدة الاحتفاظ بالتذاكر والتشخيص.
- مزود نظام التذاكر، إن لزم، ومتطلبات استضافة بياناته.
- أهداف RPO/RTO حسب نموذج النشر.
- شروط جلسات الدعم عن بُعد والمخول بالموافقة.

- [ ] معاينة حزمة التشخيص قبل الإرسال وموافقة صريحة.
- [ ] الدعم عن بُعد غير مفعل افتراضيًا، محدود المدة والغرض وقابل للإنهاء.
- [ ] وصول الدعم وتغييراته مسجلة وقابلة للمراجعة.
- [ ] إجراء قبل الإصلاحات الخطرة يشمل النسخ والاستعادة والتراجع.
- [ ] لا SLA أو توافق جهاز أو اعتماد قانوني بلا دليل وموافقة.
