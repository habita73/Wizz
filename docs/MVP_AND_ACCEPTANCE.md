# نطاق MVP ومعايير القبول — خط الأساس المعتمد

- **الحزمة المرجعية:** v0.5.4
- **حالة الوثيقة:** `APPROVED — OWNER APPROVED`
- **حالة MVP:** `APPROVED`
- **حالة التنفيذ:** `NOT AUTHORIZED`
- **قاعدة الفصل:** اعتماد النطاق لا يمنح إذنًا بالبرمجة أو إنشاء مشروع قابل للبناء أو إجراء اختبارات تنفيذية.

## 1. الهدف وحدود التجربة

إطلاق تجربة محدودة لمتجر واحد تثبت أربع نتائج فقط: (1) بيع محلي موثوق على Windows، (2) بيانات محفوظة وقابلة للاستعادة والتصدير، (3) إدارة تجارية أساسية واضحة، (4) مساعد AI مفيد لكنه خاضع للصلاحيات والتأكيدات. لا نحاول إدخال جميع وحدات الرؤية العامة في الإصدار الأول.

**افتراض تخطيطي:** مستخدم/متجر واحد في التجربة الأولى مع أدوار محلية بسيطة. لا يُعد هذا وصفًا لقطاع تجريبي محدد أو توافقًا مع جهاز لم يُختبر.

## 2. داخل MVP — النطاق المعتمد

### A. النواة الإلزامية P0

1. تطبيق Windows بواجهة عربية RTL، مع بنية تسمح بإضافة الفرنسية. تظل لغة الواجهة ولغة المساعد ولغة المستند إعدادات مستقلة؛ تُختبر الفرنسية ضمن التحقق ولا تؤخر النواة العربية ما لم تكن شرطًا للتجربة.
2. إعداد متجر واحد ومستخدمين محليين وصلاحيات أساسية؛ منع العمليات غير المصرح بها وتسجيل التغييرات الحساسة.
3. تعريف المنتجات والخدمات: الاسم، الرمز/الباركود عند توفره، الوحدة، السعر، البحث السريع ومنع التكرار الواضح.
4. إنشاء عملية بيع بمنتج واحد أو عدة منتجات، وحساب الإجمالي، والخصم ضمن الصلاحية، وتسجيل وسيلة الدفع والمدفوع والمتبقي. البيع الآجل اختياري من إعداد المتجر.
5. مستند/إيصال أساسي مرتبط بالعملية. لا يُسوّق كفاتورة قانونية أو وثيقة مطابقة قبل مراجعة مختص جزائري واعتماد المتطلبات الخاصة بالنشاط.
6. تصحيح/إلغاء موثق يحافظ على أثر العملية الأصلية. المرتجعات تدخل فقط إذا أمكن ضبط قواعدها واختبارها ضمن النطاق؛ وإلا تؤجل دون إفساد سجلات البيع.
7. قاعدة بيانات محلية، استمرار البيع الأساسي دون إنترنت، وإعادة فتح التطبيق دون فقد أو تكرار العملية.
8. نسخة احتياطية واستعادة وتصدير للبيانات الأساسية؛ لا تُقبل التجربة قبل اختبار استعادة فعلية في بيئة منفصلة.
9. تقارير تشغيلية أولية: مبيعات حسب الفترة، إجمالي التحصيل والمبالغ المستحقة. يجب بيان مصدر الأرقام، وعدم تسمية الإيراد ربحًا.
10. مساعد AI نصي بمهام محددة: الإجابة عن أسئلة من بيانات المتجر عبر أدوات مصرح بها، تلخيص المبيعات، اقتراح بحث، وصياغة مسودة رسالة/طلب أو مستند. لا SQL أو shell حر، ولا تنفيذ مالي أو إرسال خارجي دون صلاحية وتأكيد مناسب. لا يعتمد البيع على توفر AI.
11. إعدادات خصوصية صريحة: لا telemetry أو إرسال تلقائي؛ موافقة AI السحابي منفصلة عن موافقة المزامنة. لا تُفعّل المزامنة الإنتاجية ضمن MVP.
12. عرض واضح لحالة الحفظ/الفشل؛ لا إعلان نجاح قبل تأكيد العملية، ومنع تكرار الأثر عند إعادة المحاولة.

### B. وحدات اختيارية داخل التجربة P1

1. **مخزون أساسي اختياري:** رصيد افتتاحي، حركة بيع، تسوية مخولة، جرد بسيط وتنبيه انخفاض الرصيد. يجب أن تعمل المبيعات إذا عُطّل المخزون.
2. **ملف عميل ومبالغ مستحقة وتسديدات** إذا كان ضروريًا لنشاط التجربة؛ مع كشف رصيد قابل للمطابقة.
3. قارئ باركود وطابعة من الطرازات المتاحة فعليًا. يُذكر التوافق للطراز المختبر فقط؛ عدم توفر الجهاز يؤجل تكامله ولا يمنع اختبار البيع الأساسي على الشاشة.
4. استيراد من ملف جدولي مع معاينة الأخطاء والتكرار قبل التطبيق.

إذا لم تكن وحدة P1 لازمة للتجربة أو لم تتوفر أجهزة اختبارها، تُسجل صراحة خارج التجربة ولا يُدّعى أنها جاهزة.

## 3. خارج MVP

- تعدد الفروع والمزامنة الإنتاجية متعددة الأجهزة.
- تطبيق هاتف كامل أو بوابة سحابية شاملة.
- التجارة الإلكترونية، التكاملات الحكومية/البنكية، والفوترة الإلكترونية الرسمية.
- المشتريات المتقدمة، عروض الموردين، التصنيع والوصفات، الدفعات والصلاحيات المتقدمة.
- الولاء والتوصيل والأسطول والموارد البشرية والرواتب والبنوك والشيكات والتمويل والأصول والصيانة والعقود.
- محرر أتمتة عام، تنفيذ AI غير مراقب، أو أي آلية تمنح النموذج وصولًا حرًا إلى النظام.
- تسعير نهائي للباقات، بوابة دفع، أو التزامات خدمة/دعم غير مدروسة.

التأجيل يعني «ليس في الإصدار الأول»، ولا يعني رفضه من الرؤية المستقبلية.

## 4. معايير القبول الإلزامية P0

كل اختبار أدناه **مطلوب مستقبلًا ولم يُنفذ بعد**. يجب إرفاق الخطوات والبيئة والنتيجة والدليل عند تنفيذه.

| ID | الاختبار | معيار النجاح |
|---|---|---|
| MVP-AT-01 | إعداد متجر ومستخدم | تحفظ الإعدادات وهوية المتجر؛ لا يستطيع المستخدم تنفيذ ما لا تسمح به صلاحياته. |
| MVP-AT-02 | العربية وRTL | الشاشات الأساسية والنصوص والأرقام قابلة للقراءة دون تداخل أو قص جوهري. |
| MVP-AT-03 | تعريف منتج/خدمة | تُحفظ البيانات وتُكتشف الرموز المكررة وفق سياسة واضحة. |
| MVP-AT-04 | بيع مفرد ومتعدد | تطابق الإجماليات الحساب المتوقع، وتُحفظ العملية مرة واحدة. |
| MVP-AT-05 | خصم ومدفوع/متبقٍ | الصلاحيات مطبقة، والمبالغ منفصلة ومحسوبة بدقة، ولا يتحول الآجل إلى تحصيل نقدي. |
| MVP-AT-06 | مستند البيع | تتطابق القيم مع العملية؛ أي ادعاء قانوني معلق حتى المراجعة المختصة. |
| MVP-AT-07 | انقطاع الإنترنت | يستمر البيع المحلي الأساسي؛ وتظهر الخدمات غير المتاحة بوضوح. |
| MVP-AT-08 | إغلاق وإعادة فتح التطبيق | تبقى العملية بالقيم نفسها ولا تتكرر. |
| MVP-AT-09 | نسخة واستعادة | استعادة فعلية في بيئة منفصلة ومطابقة عينة من السجلات والعلاقات والأرصدة. |
| MVP-AT-10 | إجراء حساس | تُطبق الصلاحيات والتأكيدات ويُسجل الفاعل والوقت والنتيجة. |
| MVP-AT-11 | تصحيح/إلغاء | يبقى الأصل وأثر التعديل وسببه والفاعل محفوظة. |
| MVP-AT-12 | AI مع طلب واضح أو غامض | يستخدم بيانات موثوقة أو يطلب توضيحًا؛ لا يخترع قيمًا تجارية. |
| MVP-AT-13 | تعطل AI/نفاد الحصة | تظهر الحالة بصدق ويستمر البيع الأساسي. |
| MVP-AT-14 | الخصوصية | لا إرسال تلقائي؛ وموافقتا AI السحابي والمزامنة منفصلتان. |
| MVP-AT-15 | إعادة المحاولة/انقطاع أثناء الحفظ | لا تتكرر عملية بيع أو دفعة بسبب إعادة المحاولة. |
| MVP-AT-16 | تصدير البيانات | البيانات الأساسية قابلة للقراءة ولا تتضمن أسرارًا أو بيانات اعتماد. |
| MVP-AT-17 | حدود الاشتراك | انتهاء الاشتراك لا يحجب بيانات العميل أو النواة المحلية الموعودة. |
| MVP-AT-18 | سجل الاختبار | لكل نتيجة إصدار وبيئة وخطوات ودليل وحالة PASS/FAIL/BLOCKED؛ لا تُحسب الاختبارات المخططة كناجحة. |

## 5. معايير وحدات P1 عند إدخالها

- **المخزون:** تطابق حركات الدخول والخروج والتسوية الرصيد؛ البيع يعمل مع تعطيل الوحدة.
- **العملاء والديون:** كشف الرصيد يساوي العمليات والتحصيلات والتسويات المسجلة.
- **الأجهزة:** اختبار موثق على طراز فعلي مع إعداداته؛ لا ادعاء توافق عام.
- **الاستيراد:** معاينة الأخطاء والتكرار قبل الحفظ، وعدم إعادة تطبيق الملف نفسه مرتين دون تنبيه.

## 6. بوابة قبول التجربة

لا تبدأ تجربة مع تاجر قبل تحقق جميع شروط P0 التالية:

1. اجتياز كل اختبارات سلامة البيانات والصلاحيات والخصوصية ومنع التكرار والنسخ والاستعادة.
2. إغلاق المراجعة القانونية للوثيقة التجارية التي ستستخدم فعليًا، أو حصر الاستخدام صراحة في مستند غير موصوف كوثيقة قانونية إلى حين الإغلاق.
3. توثيق جهاز Windows وبيئة التخزين وأي طابعة/قارئ ضمن نطاق التجربة.
4. توثيق الحدود المعروفة وخطة الدعم والاستعادة وموافقة صاحب المشروع على بدء التجربة.
5. لا تُعد ميزات P1 متاحة إلا إذا اختُبرت وقُبلت صراحة.

## 7. القرارات والافتراضات المفتوحة

- قطاع التاجر التجريبي: غير محدد؛ لا يُفترض نشاط بعينه.
- جهاز Windows والطابعة والقارئ: غير محددة ولم تختبر.
- نوع المستند القانوني ومتطلباته: يحتاج مراجعة مختص جزائري.
- نمط التخزين/التثبيت النهائي: اتجاهه العام محلي، لكن تفاصيله تحتاج تحققًا تقنيًا مصرحًا به.
- نموذج AI المحلي/السحابي، حدوده وتكلفته: يحتاج تقييمًا قبل الالتزام التجاري.
- الميزانية والمدة والفريق: تُقدّر بعد اعتماد النطاق والتحقق من المخاطر، لا قبل ذلك.
