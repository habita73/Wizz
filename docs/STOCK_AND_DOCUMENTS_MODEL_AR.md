- **الإصدار:** 1.0 | **التاريخ:** 2026-11-14

- **المراجع الملزمة:** `PROJECT_RULES.md` (0.3.0، R-01…R-12)، `docs/TECHNICAL_AND_SAFETY_RULES.md` (0.6.1)،

---

## 1. الهدف والنطاق

يوحّد هذا التصميم مصدر الحقيقة للمخزون في **المستندات**، ويجعل رصيد المنتج المخزَّن **ذاكرة مؤقتة** قابلة لإعادة
البناء، ويضبط بوابة زمنية تمنع تغيير الماضي بعد إغلاق وردية الكاشير.

**داخل النطاق:** نموذج المستندات، الترقيم، بطاقة المخزون، الوردية وبوابة الإغلاق، ترحيل البيانات الحالية.
**خارج النطاق:** وحدة الصندوق وعدّ النقدية، المشتريات الفعلية (تُحجز كرمز `SHR`)، المزامنة الإنتاجية، الواجهات.

---

## 2. المبدأ: اعتماد أحادي الاتجاه

```
        المستندات (بيع / إلغاء / شراء / إتلاف / جرد / مرتجع)
                             │  مصدر الحقيقة الوحيد
                             ▼
              الرصيد المخزَّن (Products.StockQuantity)
                    ذاكرة مؤقتة قابلة لإعادة البناء
                             ▼
             بطاقة المخزون / التقارير / تنبيهات النقص
```

- لا يُكتب `StockQuantity` إلا داخل معاملة مستند.
- لا يعتمد مستند على رصيد أو تقرير؛ الاعتماد في اتجاه واحد فقط.
- سجل التدقيق (من/متى/لماذا) يشرح ولا يُشارك في الحساب.

## 3. الكيانات

### 3.1 `StockDocument` — مستند حركة مخزون

| الحقل | النوع | ملاحظات |
|---|---|---|
| `Id` | GUID | معرّف تقني مستقل عن الرقم الظاهر |
| `StoreId` | GUID | كل مستند لمتجر واحد؛ لا عبور بين المتاجر |
| `Type` | enum | افتتاحي / جرد / إتلاف / تالف / مرتجع بيع / شراء / تسوية |
| `Number` | string | `{CODE}-{YYYY}-{SEQ}` فريد لكل (متجر، نوع، سنة) |
| `DocumentDate` | date | التاريخ التجاري الذي يدخل التقارير |
| `CreatedAt` | datetime (UTC) | وقت الإدخال الفعلي — للتدقيق فقط |
| `CreatedByUserId` | GUID | الفاعل |
| `Reason` | string | إلزامي للإتلاف والتسوية والجرد |
| `ReferenceSaleId` | GUID? | للمرتجع والتصحيح |
| `Source` | string? | وسم الترحيل: `reconstructed` أو `synthetic` |
| `IsVoided` + `VoidedAt/By/Reason` | | إبطال مستند خاطئ بمستند عكسي، لا حذف |

### 3.2 `StockDocumentLine`

| الحقل | ملاحظات |
|---|---|
| `ProductId`, `UnitId` | الوحدة المدخلة كما أدخلها المستخدم |
| `Quantity` | بالوحدة المدخلة |
| `BaseQuantityDelta` | **موقّع**، محوَّل للوحدة الأساسية — هو ما يدخل المعادلة |
| `QuantityBefore` / `QuantityAfter` | لقطة لحظية للتدقيق، لا تُستخدم في الحساب |
| `Reason` | سبب السطر عند اختلافه عن سبب المستند |

قاعدة التحويل: `BaseQuantityDelta = ±(Unit.ToBaseQuantity(Quantity))`، ويُخزَّن الناتج بعد التقريب المعتمد في
وحدة المنتج الأساسية. أي تقريب يجب أن يكون ثابتًا ومُختبرًا (قاعدة المال العشري لا تُطبَّق على الكميات).

### 3.3 `DocumentSequence`

| الحقل | ملاحظات |
|---|---|
| `StoreId`, `DocumentType`, `Year` | مفتاح فريد مركّب |
| `LastNumber` | آخر رقم صادر |

يُحدَّث داخل معاملة المستند نفسها. التصادم يُعالج بإعادة المحاولة (حد أقصى محدد)، ويُرفض المستند إن استمر.

### 3.4 `CashierShift` — وردية الكاشير

| الحقل | ملاحظات |
|---|---|
| `Id`, `StoreId`, `CashierId` | وردية كاشير واحد في متجر واحد |
| `OpenedAt`, `OpenedByUserId` | |
| `ClosedAt`, `ClosedByUserId` | `ClosedAt = null` تعني مفتوحة |
| `Status` | مفتوحة / مغلقة |
| `SalesTotal`, `CashTotal`, `CreditTotal` | **لقطة مجمّدة** تُحسب عند الإغلاق ولا تُعاد حسابها |

**قيد أساسي:** لا يسمح بورديتين مفتوحتين لنفس الكاشير في نفس المتجر في الوقت نفسه.

**حدود المرحلة 2:** الوردية تجمّد إجماليات البيع فقط. عدّ النقدية الفعلي (الفكة، الإيداع، السحب، فرق الإغلاق)
يخص وحدة الصندوق في المرحلة 3.

### 3.5 تعديلات على `Sale`

| الحقل | الغرض |
|---|---|
| `ShiftId` | ربط البيع بالوردية التي أُنشئ فيه |
| `CancelledAt`, `CancelledByUserId`, `CancelReason` | تثبيت سبب الإلغاء والفاعل (تُهمَل اليوم) |
| `ModifiedAt`, `ModifiedByUserId`, `ModificationReason` | أثر التعديل للتدقيق فقط (R-12) |

`Sale` + `SaleItems` هما مستند البيع. **لا** تُنسخ أسطره إلى `StockDocument` ولا إلى جدول حركات.

### 3.6 مصير `StockMovement` الحالي

يُحوَّل كل صف قائم إلى `StockDocument` بالنوع المقابل (افتتاحي/جرد/تسوية) مع الحفاظ على السبب والمستخدم والتاريخ،
ثم يُجمَّد الجدول للقراءة فقط ويُهمَل بعد التحقق. لا يُكتب فيه أي صف جديد بعد الترحيل.

## 4. الأنواع والرموز

| النوع | الرمز | الإشارة | السبب المطلوب | المصدر |
|---|---|---|---|---|
| رصيد افتتاحي | `RSL` | + | لا | إنشاء منتج أو ترحيل |
| جرد | `JRD` | ± | نعم | مستند جرد |
| إتلاف / تالف | `ITL` | − | نعم | مستند إتلاف |
| مرتجع بيع | `MRB` | + | نعم | مرتبط ببيع |
| شراء (محجوز) | `SHR` | + | — | المرحلة 3 |
| تسوية | `TSW` | ± | نعم | مستند تسوية |

إضافة نوع جديد تتطلب قرارًا موثقًا ورمزًا جديدًا؛ لا يُعاد استخدام رمز قائم.

---

## 5. الترقيم

**الصيغة:** `{CODE}-{YYYY}-{SEQ}` — مثال: `JRD-2026-0001`.

1. `SEQ` تسلسل مستقل لكل (متجر، نوع مستند، سنة)، يبدأ من `0001`، بلا فجوات ولا إعادة استخدام.
2. صيغة السنة إعداد على مستوى المتجر: **4 أرقام (افتراضي)** أو رقمان. تغيير الإعداد يؤثر في المستندات الجديدة فقط،
   ولا يعيد تسمية قديم.
3. يُولَّد الرقم داخل معاملة إنشاء المستند، بعد التحقق من الصلاحية، وقبل حفظ الأسطر.
4. عند تصادم القيد الفريد: إعادة محاولة محدودة (٣ مرات)، ثم فشل صريح — لا يُصدر رقم مؤقت.
5. لا يُعدَّل رقم مستند بعد إصداره. المستند الخاطئ يُبطل بمستند عكسي ويبقى رقمه محجوزًا.

## 6. معادلة الرصيد

لكل منتج في متجر:

```
StockQuantity = OpeningStock
              + Purchases
              − ActiveSales
              + Returns
              ± CountAndWasteDeltas
```

- جميع الحدود تُحسب بالوحدة الأساسية للمنتج.
- عند تعطيل تتبع المخزون (`Store.InventoryEnabled = false`) لا تُنشأ مستندات ولا تُخصم كميات، ويبقى الرصيد مرجعًا
  إرشاديًا. الإلغاء لا يعيد كمية لم تُخصم أصلًا.
- **صيغة مكافئة:** بطاقة المخزون تعرض كل بيع كخروج بتاريخه وكل إلغاء كدخول بتاريخ الإلغاء؛ مجموعهما يساوي
  «− المبيعات النشطة». الصيغتان متكافئتان رياضياً، والاختبار الآلي يتحقق من إحداهما ويثبت التكافؤ.
- الفارق بين المعادلة والرصيد المخزَّن = **فشل اختبار**، لا تحذير.

## 7. بطاقة المخزون

تُبنى بقراءة موحّدة من المستندات، دون جدول مكرر:

```sql
-- توضيح: استعلام وصفي؛ الأسماء النهائية تُثبت في مرحلة التنفيذ
SELECT d.DocumentDate, d.CreatedAt, d.Type, d.Number,
       l.BaseQuantityDelta, d.Reason, d.CreatedByUserId
FROM StockDocuments d
JOIN StockDocumentLines l ON l.StockDocumentId = d.Id
WHERE l.ProductId = @productId AND d.IsVoided = 0

UNION ALL
SELECT s.SaleDate, s.CreatedAt, 'SALE', s.Number,
       -SUM(i.Quantity * u.FactorToBase), NULL, s.CashierId
FROM Sales s JOIN SaleItems i ON i.SaleId = s.Id
JOIN UnitsOfMeasure u ON u.Id = i.UnitId
WHERE s.StoreId = @storeId
GROUP BY s.Id

UNION ALL
SELECT s.CancelledAt, s.CancelledAt, 'CANCEL', s.Number,
       +SUM(i.Quantity * u.FactorToBase), s.CancelReason, s.CancelledByUserId
FROM Sales s JOIN SaleItems i ON i.SaleId = s.Id
JOIN UnitsOfMeasure u ON u.Id = i.UnitId
WHERE s.CancelledAt IS NOT NULL AND s.StoreId = @storeId
GROUP BY s.Id

ORDER BY 1, 2;
```

- الترتيب: `(DocumentDate, CreatedAt)` — التاريخ التجاري أولًا، ثم وقت الإدخال لفك التعادل.
- الرصيد الجاري عمود محسوب في العرض، لا يُخزَّن.
- إن ظهرت مشكلة أداء بعد سنوات من البيانات: يُضاف **Projection** قابل للحذف وإعادة البناء. لا يصبح مصدر حقيقة.

## 8. دورة حياة البيع

| الحالة | التعديل | المخزون | التقارير |
|---|---|---|---|
| بيع في وردية مفتوحة واليوم الحالي | مسموح (تعديل في مكانه + أثر تدقيق) | يُعاد احتساب الفرق داخل نفس المعاملة | يعرض القيم المصححة |
| بيع في وردية مغلقة | **مرفوض** برسالة صريحة | لا يتغير | يبقى كما أُغلق |
| بيع في يوم سابق وورديته غير مغلقة | **مرفوض** (يوم العمل الحالي فقط) | لا يتغير | يمكن إغلاق الوردية لاحقًا |
| إلغاء بيع | مسموح داخل نافذة التعديل | يُعاد كاملًا بتاريخ الإلغاء | خروج + دخول ظاهران |
| تصحيح بعد الإغلاق | بمستند `MRB`/`TSW` جديد مرتبط بالأصل | حركة جديدة بتاريخ التصحيح | لا يُمسّ الماضي |

**قاعدة النافذة:** يُسمح بالتعديل إذا تحقق الشرطان معًا: (١) وردية البيع مفتوحة، (٢) `DocumentDate` للبيع يقع في
يوم العمل الحالي. غير ذلك = مستند تصحيح.

---

## 9. الوردية

- تُفتح عند أول بيع للكاشير في يوم العمل، أو يدويًا.
- تُغلق يدويًا؛ عند الإغلاق تُحسب `SalesTotal`/`CashTotal`/`CreditTotal` وتُجمَّد.
- بعد الإغلاق لا يتغير أي رقم في الوردية، حتى لو أُلغيت مبيعات لاحقة.
- الوردية القديمة المتروكة مفتوحة: تُغلق لاحقًا وتُجمَّد عند إغلاقها، لكن لا يفتح ذلك باب تعديل مبيعاتها.
- **غير محسوم:** ساعة بداية يوم العمل. الافتراضي المقترح في MVP: منتصف الليل (00:00)، وإضافة إعداد
  `BusinessDayStartHour` مؤجلة.

## 10. الترحيل

### 10.1 الخطوات

1. نسخة احتياطية موثقة وقابلة للاستعادة قبل أي تعديل.
2. تحويل `StockMovements` القائمة إلى مستندات مع الحفاظ على السبب والفاعل والتاريخ.
3. لكل منتج: محاولة إعادة بناء الافتتاحي من المستندات والمبيعات النشطة والمرتجعات.
4. إن كانت النتيجة متسقة (افتتاحي غير سالب، وتواريخه لا تسبق أول حركة معروفة): تُعتمد وتُوسم `reconstructed`.
5. إن تعذّر: يُنشأ افتتاحي اصطناعي بفارق الوصول إلى الرصيد الحالي ويُوسم `synthetic` مع سبب الترحيل.
6. التحقق النهائي: إعادة حساب رصيد كل منتج من المستندات ومقارنته بالرصيد المخزَّن — الفارق يجب أن يكون صفرًا.
7. تقرير ترحيل: عدد المنتجات في كل مسار، والفروق، والاستثناءات.
8. تجميد `StockMovements` بعد النجاح؛ لا حذف مباشر قبل دورة تحقق كاملة.

### 10.2 شروط الإتمام

- تقرير فروق صفري.
- نسخة احتياطية مسبقة مختبرة.
- وسم مصدر واضح لكل افتتاحي.
- إمكان إعادة التشغيل دون تكرار المستندات (idempotent).

## 11. الاختبارات الإلزامية

| # | الاختبار | المعيار |
|---|---|---|
| T-01 | مطابقة الرصيد بعد بيع/إلغاء/تعديل | الرصيد المخزَّن = المعادلة، الفارق 0 |
| T-02 | بوابة الإغلاق | التعديل داخل وردية مغلقة أو يوم سابق يُرفض |
| T-03 | تجميد الوردية | إلغاء بعد الإغلاق لا يغيّر أرقامها |
| T-04 | الترقيم تحت التزامن | ٥٠ مستندًا متوازيًا = ٥٠ رقمًا فريدًا بلا فجوات |
| T-05 | التاريخ الرجعي | مستند بتاريخ سابق يظهر في ترتيبه الصحيح، و`CreatedAt` يبقى وقت الإدخال |
| T-06 | الترحيل | مطابقة كاملة، ووسم صحيح، وإعادة تشغيل لا تُكرر |
| T-07 | منع الحذف | محاولة حذف منتج له مستندات تفشل وتُقترح التعطيل |
| T-08 | تعطيل المخزون | لا مستندات ولا خصم، والإلغاء لا يعيد كمية غير مخصومة |
| T-09 | المرتجع | `MRB` مرتبط ببيع، والرصيد يزيد بقيمته فقط |
| T-10 | الوحدات | التحويل للوحدة الأساسية دقيق وثابت عبر كل الأنواع |

## 12. المراحل

| المرحلة | المحتوى | الشرط |
|---|---|---|
| **0** | اعتماد هذا التصميم والقرارات (تمّ) | — |
| **1** | `StockDocument` + `DocumentSequence` + الجرد/الإتلاف/الافتتاحي + الترحيل + بطاقة المخزون + T-01، T-04…T-08، T-10 | تفويض تنفيذ صريح |
| **2** | `CashierShift` + `Sale.ShiftId` + بوابة الإغلاق + حقول الإلغاء/التعديل + مستند المرتجع + T-02، T-03، T-09 | تفويض مستقل |
| **3** | الصندوق وعدّ النقدية، المشتريات (`SHR`)، واجهات التقارير | خارج نطاق المخزون |

المرحلة 1 تُغلق مصدر الحقيقة. المرحلة 2 تُغلق القاعدة التجارية. لا تُدمجان في تفويض واحد.

## 13. المخاطر والمسائل المؤجلة

| الخطر | الأثر | التخفيف |
|---|---|---|
| بطاقة مخزون ثقيلة مع تراكم البيانات | بطء التقارير | فهارس على `(ProductId, DocumentDate)`؛ Projection لاحقة عند الحاجة |
| ترحيل خاطئ يفسد الأرصدة | فقدان ثقة | نسخة احتياطية + تقرير فروق + إعادة تشغيل idempotent |
| وردية متروكة مفتوحة | التباس في النافذة | إغلاق يدوي إلزامي وتنبيه؛ لا تعديل لمبيعات الأمس |
| تعدد الأجهزة Offline | أرصدة متعارضة | مستندات بمعرّفات ثابتة تمهّد للمزامنة؛ لا مزامنة إنتاجية في MVP |
| حدود يوم العمل | نسبة بيع لليوم الخطأ | الافتراضي منتصف الليل؛ الإعداد ساعة البداية مؤجل |
| تقريب تحويل الوحدات | فروق صغيرة متراكمة | قاعدة تقريب واحدة مُختبرة في T-10 |

**مسائل مؤجلة:** ساعة بداية يوم العمل، عدّ النقدية وفرق الإغلاق، المرتجع الجزئي بالأسطر (يُحسم قبل المرحلة 2)،
المشتريات الفعلية، المزامنة الإنتاجية.
