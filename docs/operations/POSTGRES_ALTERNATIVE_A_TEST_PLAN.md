## 0. القرارات المعتمدة المدمجة

1. **`A-11`** يقتصر على **إزالة/إعادة تثبيت محرك PostgreSQL**. اختبار إزالة تطبيق Vent au comptoir وإعادة تثبيته يُؤجل إلى ما بعد وجود حزمة تطبيق فعلية، ويُدرج **أثر إزالة التطبيق على قاعدة البيانات** ضمن تقييم **البديل B**.
2. **`A-05`** يقتصر على **الإنهاء القسري لعملية/خدمة PostgreSQL**. لا يُدرج انقطاع الطاقة الفعلي في هذه المرحلة، **ولا تُعمَّم النتائج عليه**.
3. **`A-07`** يعتمد **التطابق المنطقي** بمستويات المقارنة الخمسة، مع **تثبيت لحظة مرجعية واحدة**، و**لا تُعد العينات المحدودة دليلًا** على التطابق الكامل.
4. **`A-08`** يفصل **فشل النسخ** عن **فشل الاستعادة**، مع **نسخة مرجعية منفصلة غير قابلة للتعديل**.
5. **`A-05` — معيار مؤكد:** تبقى `T-c` المؤكدة كاملة؛ و`T-u` غير مُلزَمة بالبقاء؛ ويُمنع أي أثر جزئي يخالف ذرّية المعاملة. **لا يُخلط بين سجل معرّف المعاملة وأثرها الملتزم في القاعدة.**
6. **`A-06`/`A-07` — قيد التجميد:** **لا يُرفع تجميد الكتابة إلا بعد إثبات اكتمال النسخة الاحتياطية واستقرار بصمتها**، وبشرط أن تكون **آلية النسخ متوافقة مع نافذة التجميد**. إذا تعذر إثبات اتساق المصدر والنسخة، تُصنَّف `A-07` بأنها **`BLOCKED`** وتبقى **بوابة M3 مغلقة**.

## 1. الهدف والنطاق والقيود

**السؤال الحاكم:** هل تشغيل PostgreSQL كخدمة Windows عملي بما يكفي ليكون أساسًا لتوزيع Vent au comptoir على جهاز تاجر واحد، مع بيع محلي دون إنترنت؟

**داخل النطاق:** تثبيت الخدمة وتشغيلها محليًا؛ الاستماع الآمن؛ البدء التلقائي؛ استمرارية البيانات؛ التعافي من إنهاء قسري؛ النسخ والاستعادة؛ حماية النسخة المرجعية؛ الأدوار والصلاحيات؛ إزالة/إعادة تثبيت **المحرك** مع حفظ البيانات.

**خارج النطاق:** تطوير مثبّت أو حزمة تطبيق (البديل B)؛ أي تطبيق أو نموذج اختباري (`I`)؛ إزالة/إعادة تثبيت **تطبيق Vent au comptoir**؛ المزامنة السحابية؛ تعدد الأجهزة؛ انقطاع الطاقة الفعلي؛ الترقية (`A-10` مؤجل)؛ الموارد (`A-12` مؤجل)؛ الأداء التفصيلي؛ الامتثال القانوني؛ الأجهزة الطرفية؛ AI.

**قيود إلزامية:** بيانات اصطناعية فقط؛ لا بيانات تاجر؛ لا VPS؛ لا Docker إنتاجي؛ لا تعديل كود أو Solution؛ لا تغيير إعدادات نظام خارج البيئة المعزولة؛ **لا إغلاق لـ`G-03`**؛ نجاح الاختبارات لا يُعد جاهزية إطلاق.

## 2. شروط البيئة المعزولة ومتطلبات السلامة

| الشرط | التفصيل |
|---|---|
| البيئة | VM أو محطة معزولة قابلة للرمي، مع **لقطة نظام** قبل كل خطوة مُدمِّرة |
| البيانات | اصطناعية فقط؛ ممنوع أي بيانات حقيقية |
| الشبكة | معزولة؛ **ممنوع منفذ عام**؛ لا VPS |
| **النسخة المرجعية** | سليمة، **منفصلة عن مجلد البيانات وعن القرص نفسه**، و**غير قابلة للتعديل**، ببصمة مسجّلة قبل/بعد كل اختبار |
| النسخ القابلة للرمي | منفصلة تمامًا، وتُستخدم **فقط** لإحداث الفشل في `A-08` |
| مبدأ الكتابة | **يُمنع قطعًا** اختبار الكتابة فوق النسخة المرجعية الوحيدة الصالحة |
| مبدأ التنفيذ | اختبار واحد = متغير واحد؛ لا خطوات مُدمِّرة قبل بوابة `A-07` |
| الصلاحيات | حساب إداري **في البيئة المعزولة فقط** (لتسجيل الخدمة) |
| التسجيل | معرّف، تاريخ، بيئة (إصدار Windows/PostgreSQL، العتاد)، خطوات، نتيجة متوقعة/فعلية، أدلة، `PASS/FAIL/BLOCKED`، عيوب — لا `PASS` بلا دليل |

**بوابتان لا تُجازان:**
1. `A-02` — بوابة أمنية مبكرة تمنع أي اختبار لاحق عند الفشل.
2. **`A-07` شرط إلزامي** قبل `A-05` و`A-08`؛ **وجود نسخة لا يعني صلاحيتها**، ولا يُرفع تجميد الكتابة إلا بعد إثبات اكتمال النسخة الاحتياطية واستقرار بصمتها (القرار 6).

## 3. الاختبارات العشرة

### M1 — الإعداد غير المُدمِّر

#### `A-01` — تثبيت PostgreSQL كخدمة Windows وتشغيله محليًا

- **الهدف:** إثبات قابلية التثبيت كخدمة على Windows نظيف، بخطوات موثّقة.
- **المتطلبات:** لقطة نظام نظيفة؛ مصدر تثبيت موثّق؛ صلاحيات مسؤول؛ إصدار PostgreSQL محدد مسبقًا.
- **الخطوات:** تثبيت نظيف → ضبط اعتماد الدور الفائق → التحقق من الخدمة → اتصال محلي فقط للتحقق → تسجيل كل خطوة يدوية.
- **معيار النجاح:** خدمة تعمل + اتصال محلي ناجح + إجراء قابل للتكرار.
- **معيار الفشل:** خدمة لا تبدأ/خطوات غامضة/تعارض منفذ.
- **المخاطر:** بقايا إعدادات؛ خطأ اعتماد.
- **التوقف والرجوع:** توقف عند خطأ غير مفسّر؛ الرجوع = لقطة نظام.
- **الأدلة:** سجل الخطوات، حالة الخدمة، مخرجات الاتصال.

#### `A-02` — الاستماع والمنفذ والجدار (بوابة أمنية)

- **الهدف:** إثبات **عدم تعرية PostgreSQL للشبكة العامة**.
- **المتطلبات:** `A-01`.
- **الخطوات:** فحص إعداد الاستماع (محلي فقط) → فحص الجدار → فحص الاستماع الفعلي من النظام → فحص مصادقة الاتصال → محاولة اتصال من جهاز آخر (تحقق إيجابي) إن أمكن.
- **معيار النجاح:** لا استماع عام + منفذ غير مكشوف + مصادقة مقيّدة.
- **معيار الفشل:** أي تعرية.
- **المخاطر:** إضعاف الحماية بالخطأ.
- **التوقف والرجوع:** **يُمنع أي اختبار لاحق قبل اجتيازها**؛ عند الفشل يُغلق الاتصال فورًا.
- **الأدلة:** مخرجات الفحوص (بلا أسرار).

#### `A-03` — البدء التلقائي بعد إعادة تشغيل Windows

- **الهدف:** استمرارية تشغيل يومية دون تدخل.
- **المتطلبات:** `A-01`؛ وضع بدء مضبوط.
- **الخطوات:** إعادة تشغيل فعلية → التحقق من البدء التلقائي → الاتصال بعد الإقلاع → ملاحظة وقت الجاهزية.
- **معيار النجاح:** عودة تلقائية وقابلية اتصال.
- **معيار الفشل:** عدم العودة/وضع يدوي غير مقصود.
- **المخاطر:** سياسة بدء متعارضة؛ تأخر إقلاع.
- **التوقف والرجوع:** عند الفشل يتوقف المسار حتى الفهم (الاستمرارية شرط أساسي).
- **الأدلة:** سجل الإقلاع وحالة الخدمة.

#### `A-04` — استمرارية البيانات بعد إعادة تشغيل النظام

- **الهدف:** بقاء بيانات اختبارية كما هي بعد دورة تشغيل كاملة.
- **المتطلبات:** `A-03`؛ بيانات اختبارية ببصمة معرّفة.
- **الخطوات:** كتابة بيانات → بصمة → إعادة تشغيل النظام → قراءة ومقارنة كاملة.
- **معيار النجاح:** تطابق تام قبل/بعد.
- **معيار الفشل:** أي فقد/تحريف/اختلاف.
- **المخاطر:** مقارنة ناقصة.
- **التوقف والرجوع:** توقف عند أي اختلاف؛ رجوع = لقطة + نسخة.
- **الأدلة:** بصمات قبل/بعد.

### M2 — إثبات النسخ والاستعادة (بوابة المخاطر)

#### `A-06` — نسخة احتياطية متسقة مع لحظة مرجعية موحّدة

- **الهدف:** إنتاج نسخة صالحة قابلة للتحقق مع **تثبيت لحظة مرجعية واحدة**.
- **المتطلبات:** `A-04`؛ مسار/وسيط منفصل عن مجلد البيانات.
- **الخطوات:** فتح **نافذة تجميد الكتابة (Quiesce Window)** → تنفيذ النسخة داخل النافذة → حساب بصمة الملف → تسجيل الإصدار والحجم والزمن.
- **معيار النجاح:** ملف ذو بصمة مستقرة ومقروء، واكتمال النسخة مُثبت داخل النافذة.
- **معيار الفشل:** خطأ غير مفسّر/ملف غير قابل للقراءة/نسخة جزئية.
- **المخاطر:** نسخة على القرص نفسه (مرفوضة)؛ عدم توافق آلية النسخ مع نافذة التجميد.
- **التوقف والرجوع:** توقف عند فشل الأداة؛ لا إجراء مُدمِّر في هذه المرحلة.
- **الأدلة:** بصمة الملف، إصدار الأداة، طوابط النافذة.

**شرط «اللحظة المنطقية الواحدة» (إلزامي ومشترك مع `A-07`):**

1. **الفتح:** تُمنع كل الكتابة على المصدر (رفض/قطع اتصالات الكتابة، وإنهاء الجلسات الكاتبة، والتحقق الإيجابي من أن **عدد معاملات الكتابة النشطة = صفر**) قبل بدء النسخ.
2. **التنفيذ:** تُؤخذ البصمة المرجعية **ويُنفَّذ النسخ الاحتياطي داخل النافذة نفسها**، وتُسجَّل طوابط بداية/نهاية النافذة.
3. **الرفع (القرار 6):** **لا يُرفع تجميد الكتابة إلا بعد إثبات اكتمال النسخة الاحتياطية واستقرار بصمتها**، وبشرط أن تكون **آلية النسخ متوافقة مع نافذة التجميد**.
4. **الاستثناء الوحيد:** إذا كانت الأداة تنتج لقطة متسقة بذاتها (نسخة فيزيائية متسقة، أو تفريغ داخل معاملة واحدة بعزل متكرر)، فتُقبل **فقط** إذا أمكن **إثبات لحظة اللقطة المشتركة** ومطابقة البصمة المأخوذة على الحالة نفسها؛ وإلا تُعدّ «آلية غير متوفرة».
5. **قاعدة الحسم:** **يُمنع** الاعتماد على بصمة مأخوذة في وقت مختلف عن وقت النسخ دون آلية تضمن الاتساق. وإن تعذر إثبات الاتساق: تُصنَّف `A-07` (ومن ثمّ `A-06` كشرط لها) بأنها **`BLOCKED`**، **ولا يُدَّعى أي تطابق أو صلاحية نسخة**، وتبقى **بوابة M3 مغلقة**.

#### `A-07` — استعادة معزولة وإثبات التطابق المنطقي (بوابة M3)

- **الهدف:** إثبات صلاحية النسخة **فعلًا**، واكتمال البيانات المستعادة وفق تعريف معتمد — **والعينة المحدودة ليست دليلًا**.
- **المتطلبات:** `A-06` مع نافذة التجميد المكتملة وطوابطها.
- **الخطوات:**
  1. توليد «المخطط المرجعي» من المصدر بنفس الأداة/الترتيب/الترميز، ويشمل:
     - مخطط القاعدة (جداول/أعمدة/أنواع/قيود/فهارس) نصًّا مرتّبًا؛
     - عدد الصفوف لكل جدول؛
     - **بصمة محتوى لكل جدول** (تفريغ مرتّب بمفتاح أساسي ثم بصمة) — وليس `LIMIT n`؛
     - المجاميع العشرية الحساسة؛
     - قيم التسلسلات النشطة.
  2. استعادة في **هدف نظيف منفصل** بلا مخطط/بيانات مسبقة.
  3. إعادة توليد «المخطط المرجعي» من المستعاد بنفس الأداة/الترتيب.
  4. المقارنة على **المستويات الخمسة** + فحص سلامة القيود (لا صفوف يتيمة/مخالفة).
- **معيار النجاح:** تطابق 100% في المستويات الخمسة، بلا أخطاء قاتلة (التحذيرات تُسجَّل وتُصنَّف).
- **معيار الفشل:** أي فرق/تعذر توليد بصمات/استعادة ناقصة أو جزئية.
- **المخاطر:** استعادة جزئية تُخفي فشلًا؛ اختلاف أداة/ترتيب يُبطل المقارنة.
- **التوقف والرجوع:** عند الفشل **تُمنع M3 كاملة**. وعند تعذر إثبات اللحظة المشتركة: **`BLOCKED`** لا `FAIL`.
- **حدود معلنة:** التطابق **منطقي لا فيزيائي** (مواقع صفحات/OIDs/طوابع كائنات لا تُحتسب)؛ الاستثناءات غير الدلالية تُعلن **قبل** التنفيذ ولا تُوسَّع بعده؛ البصمات صالحة فقط ضمن نفس الأداة/الترتيب/الترميز؛ الاختبار يقيس اكتمال البيانات على مستوى القاعدة **فقط** (لا تطبيق/أداء/أمن).
- **الأدلة:** تقرير المقارنة الخمسية + البصمات + سجل الاستعادة + طوابط نافذة التجميد + قائمة الاستثناءات.

### M3 — المُدمِّر (مقيّد ببوابة `A-07`)

#### `A-05` — التعافي بعد إنهاء قسري (عملية/خدمة PostgreSQL فقط)

- **النطاق المقيد:** **الإنهاء القسري فقط**؛ لا انقطاع طاقة، **ولا تُعمَّم النتائج عليه**.
- **المتطلبات:** `A-01` + `A-06` + `A-07` (نسخة صالحة واستعادة مُثبتة) + لقطة نظام.
- **تصنيف المعاملات:**
  - `T-c` **مؤكدة ومُعلَنة** → **يجب** بقاؤها كاملة.
  - `T-u` **جارية غير مؤكدة** → **لا يُشترط بقاؤها**؛ فقدانها الكامل ليس فشلًا.
  - **الذرّية:** يُمنع أي أثر جزئي؛ أثر المعاملة إمّا كامل أو غائب.
- **الخطوات:** حمل اختباري يتضمن معاملات `T-c` مؤكدة مع تسجيل تأكيدها، ومعاملات `T-u` جارية معرّفة الحمولة → إنهاء قسري للعملية/الخدمة أثناء النشاط → إعادة تشغيل → فحص السلامة → **التحقق من الأثر الملتزم في القاعدة** (صفوف/بيانات `T-c`) ومقارنته بسجل التأكيد → التحقق من غياب أي أثر جزئي لـ`T-u`.
- **معيار النجاح:**
  1. القاعدة تعمل بعد إعادة التشغيل بلا تدخل يدوي غير موثّق؛
  2. كل `T-c` موجودة كاملة **بحسب أثرها الملتزم في القاعدة**؛
  3. لا أثر جزئي لأي `T-u` (غياب كامل أو اكتمال كامل — لا حالة وسط)؛
  4. لا صفوف يتيمة/مخالفة للقيود؛
  5. أدوات فحص السلامة لا تُظهر تلفًا.
- **معيار الفشل:** فقدان أي `T-c`؛ أثر جزئي لأي `T-u`؛ تلف؛ إصلاح يدوي غير موثّق؛ تعذر الفحص.
- **تحذير:** **لا يُخلط بين سجل معرّف المعاملة وبين أثرها الملتزم في القاعدة**؛ الحكم يكون على البيانات الملتزمة الظاهرة، لا على وجود المعرّف في سجل.
- **المخاطر:** الأعلى في المجموعة (تلف مخزن البيانات).
- **التوقف والرجوع:** يُمنع قبل إثبات `A-07`؛ عند أي شذوذ → إيقاف كامل + استعادة من النسخة المرجعية + اللقطة.
- **الأدلة:** سجل التأكيد، لقطة الحالة، نتيجة الفحص، مقارنة `T-c`، إثبات غياب أثر `T-u`.

#### `A-08` — فشل النسخ وفشل الاستعادة (حالتان مفصولتان)

**مشترك:** النسخة المرجعية **بمنأى تام وغير قابلة للتعديل**، وبصمتها تُتحقق قبل/بعد كل حالة؛ أي تغيّر فيها = **stop-the-line وفشل مُعلن**. كل الإجراءات على نسخ/أهداف **قابلة للرمي**.

**`A-08a` — فشل إنشاء النسخة:**

- **الخطوات:** إحداث فشل على **وجهة قابلة للرمي فقط** (غير قابلة للكتابة/مساحة غير كافية محاكاةً/مصدر غير متاح) → مراقبة السلوك → فحص وجود ملف جزئي.
- **معيار النجاح:** خطأ واضح + **لا ملف جزئي يُقدَّم كنسخة صالحة** + المرجع سليم ببصمة متطابقة.
- **معيار الفشل:** نجاح كاذب/ملف جزئي يبدو صالحًا/أي تغيّر في المرجع.

**`A-08b` — فشل الاستعادة:**

- **الخطوات:** استعادة من **نسخة قابلة للرمي معيبة عمدًا** إلى هدف معزول → مراقبة الخطأ → **عزل الهدف الفاشل** → **إعادة تهيئته أو التخلص منه** → استعادة ناجحة من نسخة سليمة → التحقق من بصمة المرجع.
- **العزل قبل المحاولة الناجحة (إلزامي):**
  1. **العزل الفوري للهدف الفاشل:** إيقاف الهدف/فصل اتصالاته، وإبطال اعتمادات الوصول إليه، ووسمه بوضوح كـ**«هدف استعادة فاشل — محجوز»** بحيث لا تستخدمه أي خطوة أو اختبار آخر، **ويُمنع** استخدامه كمصدر بيانات أو كقاعدة «صالحة» لأي غرض.
  2. **توثيق حالته:** رسالة الخطأ، وما تبقّى من كائنات/مخطط جزئي، وبصمة حالته إن أمكن — **بلا أي إصلاح تجميلي للهدف**.
  3. **إعادة التهيئة أو التخلص منه:** إما **إعادة تهيئة كاملة** (إسقاط/إعادة إنشاء المثيل أو القاعدة الهدف)، وإمّا **التخلص منه** (تدمير البيئة القابلة للرمي) واستخدام هدف **جديد نظيف** بالكامل؛ وفي كل الأحوال **يُمنع** تنفيذ الاستعادة الناجحة على الهدف نفسه دون إعادة تهيئة/تدمير مثبت.
  4. **التحقق قبل المحاولة الناجحة:** التأكد من أن الهدف الجديد/المعاد تهيئته **خالٍ تمامًا** من أي مخطط أو بيانات متبقية، ومسجّل كهدف جديد.
  5. **المحاولة الناجحة:** استعادة من النسخة الجيدة على الهدف النظيف → تحقق من التطابق حسب المعايير → **التحقق ببصمة أن النسخة المرجعية لم تتغير خلال كامل التسلسل**.
- **معيار النجاح:** خطأ واضح + حالة هدف معرّفة + **عزل وإعادة تهيئة/tخلص مثبتان** + إعادة استعادة ناجحة من نسخة سليمة + المرجع سليم.
- **معيار الفشل:** نجاح كاذب/قاعدة جزئية تُقبل كصحيحة/استخدام الهدف الفاشل قبل عزله/تنفيذ الاستعادة الناجحة على هدف غير معاد تهيئته/أي تغيّر في المرجع.
- **المخاطر:** المساس بالمرجع إن لم يُعزل — ولذلك العزل شرط مسبق.
- **التوقف والرجوع:** **يُمنع قطعًا** لمس النسخة المرجعية الوحيدة الصالحة؛ عند أي أثر عليها يتوقف الاختبار ويُصنَّف فشلًا.
- **الأدلة:** بصمات قبل/بعد، رسائل الفشل، سجل العزل وإعادة التهيئة، سجل الحماية.

### M4 — الصلاحيات ودورة حياة المحرك

#### `A-09` — الأدوار وأقل صلاحية

- **الهدف:** فرض أقل صلاحية فعلية.
- **المتطلبات:** `A-01` (غير مُدمِّر، يمكن تنفيذه بعد M1).
- **الخطوات:** إنشاء دور تطبيق محدود ودور إداري منفصل → اختبار حدود الوصول من الدور المحدود → تسجيل مصفوفة النتائج.
- **معيار النجاح:** لا وصول زائد + فصل واضح.
- **معيار الفشل:** صلاحيات فضفاضة/أدوار مشتركة.
- **المخاطر:** كتابة اعتمادات في وثائق/سجلات (مرفوضة).
- **التوقف والرجوع:** توقف عند أي وصول غير مقصود؛ رجوع = إسقاط الأدوار.
- **الأدلة:** مصفوفة صلاحيات وسجل محاولات.

#### `A-11` — إزالة/إعادة تثبيت **محرك PostgreSQL** مع حفظ البيانات

- **النطاق المعتمد:** المحرك فقط. **مستبعد تمامًا:** أي سلوك يخص إزالة/إعادة تثبيت تطبيق Vent au comptoir (يُؤجل إلى ما بعد وجود حزمة تطبيق فعلية؛ ويُقيَّم أثر إزالة التطبيق على قاعدة البيانات ضمن **البديل B**).
- **المتطلبات:** `A-04` + `A-07` (نسخة مُثبتة الاستعادة) + لقطة نظام.
- **الخطوات:** إزالة المحرك بالأداة الرسمية **دون حذف مجلد البيانات** → التحقق من بقاء المجلد وسلامته → إعادة تثبيت المحرك → إعادة الربط بالبيانات القائمة → التحقق بالبصمة والمقارنة.
- **معيار النجاح:** البيانات تبقى وتُقرأ بلا تدخل يدوي غير موثّق.
- **معيار الفشل:** فقدان/تلف/تعذّر ربط.
- **المخاطر:** أداة الإزالة تحذف مجلد البيانات؛ مسارات متبقية.
- **التوقف والرجوع:** عند الفشل → استعادة فورية من المرجع + اللقطة، وإيقاف بقية المجموعة.
- **الأدلة:** حالة المجلد قبل/بعد، المقارنة، إعدادات إعادة الربط.

## 6. ما تُثبته النتائج وما لا تُثبته + التوثيق

**تُثبِت (ضمن البيئة المختبرة فقط):** قابلية التثبيت كخدمة؛ البدء التلقائي؛ بقاء البيانات عبر إعادة التشغيل؛ التعافي من إنهاء قسري (لدى `T-c`، وذرّية `T-u`)؛ صلاحية النسخ بإثبات الاستعادة والتطابق المنطقي؛ عدم التعرية الشبكية؛ قابلية تقييد الأدوار؛ حفظ البيانات عند إعادة تثبيت **المحرك**.

**لا تُثبِت:** جاهزية المنتج أو القبول الكامل لـMVP؛ توافق جهاز تاجر فعلي (غياب `G-02`)؛ الأداء (`A-12` مؤجل)؛ الترقية (`A-10` مؤجل)؛ **سلوك انقطاع الطاقة** (خارج نطاق `A-05` هذا)؛ التكامل مع التطبيق وعدم التكرار من منظور التطبيق (`I`)؛ **إزالة/إعادة تثبيت التطبيق** (مؤجل)؛ المزامنة السحابية وتعدد الأجهزة؛ الامتثال القانوني؛ العربية/RTL؛ الأجهزة الطرفية؛ AI. **ولا تُغلق `G-03` تلقائيًا.**

**التوثيق لاحقًا (عند الإذن):** سجل لكل اختبار: المعرّف، التاريخ/المدة، البيئة (إصدار Windows/PostgreSQL، المعدات)، الخطوات القابلة للتكرار، النتيجة المتوقعة/الفعلية، الأدلة (سجلات، بصمات، قياسات)، الحالة `PASS/FAIL/BLOCKED`، العيوب، والقرار — وفق `AGENTS.md §12.3` و`MVP AT-18`. **مكان حفظ السجلات داخل المستودع لم يُحسم.**
