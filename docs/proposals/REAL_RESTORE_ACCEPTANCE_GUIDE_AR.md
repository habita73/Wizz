# دليل تنفيذ اختبار الاستعادة في بيئة تشغيل فعلية — مقترح

- **الحالة:** `PROPOSED` — يحتاج موافقة Farid. لا يُدرج في `MANIFEST.json`، ولا يغيّر حالة أي بوابة أو معيار قبول.
- **التاريخ:** 2026-11-17
- **المرجع:** `docs/MVP_AND_ACCEPTANCE.md` (بند النسخ والاستعادة في معايير القبول)،
  `docs/DECISIONS_AND_OPEN_GATES.md` (فقرة اختبار الاستعادة بتاريخ 2026-11-17).
- **الهدف:** توفير مسار واضح لإغلاق البند المتبقي: **استعادة فعلية في بيئة تشغيل منفصلة، مع مطابقة عينة من
  السجلات والعلاقات والأرصدة**.

> **لماذا هذا الملف؟** أُجري اختبار استعادة ببيانات اصطناعية على نفس الجهاز (قاعدة ومجلد ومنفذ منفصلان)
> نجح، وطابقت لقطة شاملة 13 جدولًا بين المصدر والوجهة. لكنه لا يُغلق البند لأنه ليس بيئة تشغيل التاجر.
> Docker Desktop أيضًا لا يُغلقه: لا يوجد دعم حاوية في المشروع، والحاوية تظل بيئة اختبار، وخطط العمليات
> تشترط «لا Docker إنتاجي». لذلك أُعدّ هذا الدليل بدل إنشاء حاوية.

---

## 1. ما المطلوب توفيره منك

1. **بيئة الهدف:** جهاز Windows ثانٍ، أو حساب مستخدم Windows نظيف، عليه نفس إصدار التطبيق المستخدم في
   المصدر. يُفضَّل تثبيت نظيف من حزمة الإصدار لا نسخة مجلد مُستعار.
2. **النسخة المرجعية:** ملف نسخة احتياطية `.db` أُخذ من بيئة فيها مبيعات وأرصدة، محفوظ خارج مجلد التطبيق.
3. **اللقطة المرجعية:** أسماء وأرقام من المصدر قبل الاستعادة، تُدوَّن في جدول المقارنة في القسم 2.1.
4. **شخص منفّذ:** لديه صلاحية تشغيل التطبيق والوصول إلى صفحة الإعدادات في البيئة الهدف.

---

## 2. خطوات التنفيذ

### 2.1 في المصدر قبل أخذ النسخة

سجّل القيم الآتية في جدول المقارنة:

| العنصر | القيمة |
|---|---|
| اسم المتجر | |
| عدد المنتجات / أرصدة منتجين محددين | |
| عدد المبيعات / إجمالي المبيعات / المتبقي | |
| عدد بنود المبيعات | |
| عدد حركات المخزون وحركات الصندوق | |
| رقم آخر مستند شراء (`SHR`) وعدد بنوده | |
| اسم المستخدم المدير | |

ثم من صفحة الإعدادات: زر **نسخة جديدة**، وسجّل اسم الملف الناتج وحجمه.

### 2.2 نقل النسخة

انسخ ملف `.db` إلى وسيط أو مجلد خارج المصدر، ودوّن اسمه وحجمه وبصمته (`SHA-256`). لا تُعدّل محتواه.

### 2.3 تجهيز البيئة الهدف

1. شغّل التطبيق أول تشغيل بقاعدة جديدة، وأكمل إعداد المدير إن طُلب.
2. تأكد أن الهدف **مختلف فعلًا** عن المصدر: اسم متجر آخر، أو عدد منتجات آخر، أو صفر مبيعات.
3. انسخ ملف النسخة إلى مجلد `Backups` الخاص بالتطبيق في البيئة الهدف.
4. تأكد أن النسخة القديمة التي تسبق المرحلة 3 غير مستخدمة؛ النسخ المقبولة تحتوي جدول `CashMovements`.

### 2.4 الاستعادة والتحقق

1. افتح صفحة الإعدادات، واختر النسخة المنقولة، واضغط **استعادة**، ثم أكّد تحذير الاستبدال.
2. أعد تشغيل التطبيق، وسجّل الرسالة التي تظهر.
3. قارن كل عناصر الجدول في 2.1 مع اللقطة المرجعية.
4. تحقق من العلاقات لا من الأرقام وحدها: فاتورة وبنودها، حركة مخزون مرتبطة بالمنتج، حركة صندوق
   مرتبطة بالوردية، مستند شراء وبنوده، وتسلسل الترقيم.
5. افتح سجل التدقيق وتحقق من سطر الاستعادة: اسم النسخة، نتيجة النجاح، ووجود نسخة أمان
   `wizz_prerestore_*` إلى جانبها.
6. تأكد أن جدول `CashMovements` موجود بعد الاستعادة.

## 3. معايير الحكم

**يُقبل الاختبار إذا تحققت كلها:**

- كل القيم والعلاقات في جدول المقارنة متطابقة مع المصدر.
- رسالة نجاح الاستعادة ظهرت بعد إعادة التشغيل.
- سطر التدقيق موجود، ونسخة الأمان أُنشئت، وجدول `CashMovements` سليم.

**يُوقف ولا يُغلق البند إذا:**

- ظهر أي اختلاف غير مبرر في الأرصدة أو العلاقات.
- تعذّر تفسير انحراف؛ يُوثَّق كما هو ويُعرض على Farid، ولا يُصحَّح بافتراض.
- استُخدمت نسخة تفتقر إلى `CashMovements`.

---

## 4. الدليل المطلوب تسجيله

| الدليل | المطلوب |
|---|---|
| اسم النسخة + الحجم + البصمة | لتأكيد أنها النسخة المنقولة نفسها |
| جدول المقارنة قبل/بعد | قيم المصدر والهدف لكل عنصر |
| رسالة التطبيق بعد الاستعادة | نص الرسالة كما ظهرت |
| سطر التدقيق | اسم النسخة + النتيجة + التاريخ |
| اسم نسخة الأمان | لإثبات إنشاء `wizz_prerestore_*` |
| بيئة التنفيذ | اسم الجهاز/المستخدم + إصدار التطبيق + التاريخ |

---

## 5. قيود ملزمة

- بيانات التاجر الحقيقية لا تُكتب في الوثائق ولا في المحادثات؛ تُستخدم أسماء وأرقام بديلة عند التوثيق.
- لا Docker كبديل عن بيئة التشغيل الفعلية، ولا إنشاء صورة حاوية دون إذن تنفيذ صريح.
- لا تغيير في Windows أو VPS أو جدار الحماية أو إعدادات الشبكة دون أمر صريح.
- لا يُعدّ الاختبار ناجحًا ولا يُرفع حالة البند قبل تسجيل الدليل الفعلي في الملف النشط.
- هذه وثيقة مقترحة فقط، ولا تُعد إذنًا بتنفيذ أي خطوة من خطواتها.

---

## 6. الحالة الحالية

- الاختبار المحلي الموسّع: **منفَّذ**، بنتيجة إيجابية، وموثّق في سجل القرارات.
- الاستعادة في بيئة تشغيل فعلية: **لم تُنفَّذ** — بانتظار توفير المتطلبات في القسم 1.
- الخطوة التالية المقترحة: يوفّر Farid البيئة والنسخة، ثم تُنفَّذ الخطوات أعلاه ويُسجَّل الدليل.
